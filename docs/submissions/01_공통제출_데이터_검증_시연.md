작성일: 2026-11-10. 대상: 교육시설 감염병 근거 기반 대응 Q&A(GraphRAG).

이 문서는 [노션 프로젝트 제출 요건](https://www.notion.so/40823bb2243780cca0f6f5be390b91e8)의 ‘공통 제출 정리’ 중 데이터 및 전처리 설명, 검증 기록, 시연 가능한 상태를 정리한다. README는 기존 문서를 유지한다. 필수 산출물 ①·②의 상세 근거는 [두 번째 제출 문서](02_필수산출물_추출_지식그래프.md)로 연결한다. KPT는 개인 확인 없이 대신 작성하지 않으며, 말미에 기존 회고 자료를 연결했다.

## 1. 데이터와 활용 범위

학교 교직원이 감염병 발생 시 수행할 행동·담당자·대응 단계와 질병별 기준·법령 근거를 찾도록 공식 매뉴얼·질병 지침·법령을 선정했다. 문서별 표현과 판본을 유지한 채 동일 행동 개념을 연결하는 것이 목표다. 의료기관·보건소 내부 업무를 학교의 행동으로 바꾸지 않는다.

| 문서군 | 출처·판본 | 활용 범위 | 담당 |
|---|---|---|---|
| 교육부 학교 감염병 예방·위기대응 매뉴얼 | 교육부, 제3차 개정판, 2023.12 | 학교 발생 시 대비·대응, 등교중지, 제5장 전체, 주요 질병 부록, 모의훈련 | 주승우 |

총 10개 문서의 **문서 ID·공식 URL·판본·선정 쪽수·비고**는 [source_manifest.csv](../../data/specs/source_manifest.csv)가 기준이다. 법령 시행일·일부 URL·이용조건에 ‘확인 필요’가 남아 있으므로 모두 확정된 자료로 표현하지 않는다. 경기도 ID의 `2025`와 실제 판권 2024.05도 구별한다.

- 선정 쪽수는 PDF 파일 순서의 **1-based** 쪽수다. 학교 자료는 교육부 `36, 38, 40, 42~44, 48~80, 104~118, 191~226`, 경기도 `156~217, 236~272, 300~301, 307~310, 349~352, 388~396`을 중심으로 하되 예외는 manifest 비고를 따른다. 교육부 결핵 상세 절 제외 등 혼합 페이지 예외를 포함한다.
- 원본 형식은 PDF이며, 본문·표를 Markdown으로 변환한 작업본에서 청크를 만든다. 그림 내부 표·흐름도는 텍스트 변환만으로 완전 추출했다고 주장하지 않는다.
- [원본·중간 산출물 정책](../../data/README.md): `data/raw/`, `data/interim/`은 Git 제외다. 공식 원문 확보와 로컬 산출물 전달 없이 새 PC에서 추출·재적재 전체를 바로 재현할 수는 없다. 공개 문서라도 재배포 이용조건은 별도 확인 대상이다.
- `.env`, URI·비밀번호·API 키는 제출하지 않는다. [환경변수 예시](../../.env.example)는 키 이름만 제공한다.

## 4. 시연 가능한 상태와 재실행

### 4.1 준비 환경

Python 3.12와 uv, Neo4j Aura 프로젝트 접속, OpenAI API가 필요하다. `uv sync`로 의존성을 설치하고 `.env.example`을 참고해 루트 `.env`를 구성한다. 실제 비밀 값은 제출하지 않는다. 모델별 설정과 Streamlit 배포 항목은 [기존 실행 안내](../../README.md#4-실행-환경의존성모델-설정환경변수)를 따른다.

```powershell
uv sync
uv run --with streamlit streamlit run src/rag/ui/app.py
```

메인 서비스는 `질문→라우팅→검색 Tool→근거/경로 검증→LLM 근거 선별→답변·줄 검사`로 동작한다. 운영 경계는 QueryInput/QueryOutput, ToolInput/ToolResult다. 이번 제출 작업에서 배포 상태나 서비스 응답을 다시 확인한 것은 아니다.

### 4.2 시연 A — 문서 입력부터 적재까지의 연결 설명

1. manifest의 선정 쪽수와 로컬 PDF·Markdown을 준비한다.
2. [학교 청크 노트북](../../notebooks/school/school_chunks_full.ipynb)에서 문서 ID·PDF 쪽수·본문/표 행 청크를 확인한다.
3. 추출 노트북에서 LLM 후보와 원문 evidence를 비교하고 검수한다. 승인된 후보만 정규화한다.
4. [학교 적재 노트북](../../notebooks/school/school_load.ipynb)과 [파일 지도](../../notebooks/school/파일_지도_무엇이_어디에.md)로 적재 패키지·검증·임베딩을 연결한다.
5. 이미 적재된 공동 DB를 조회해 동일 chunk_id와 행동의 SUPPORTED_BY를 확인한다.

이 순서는 **단계 연결 안내**다. 원본과 중간 패키지는 Git 제외이고 재적재는 승인된 쓰기 작업이므로, 제출 파일을 열었다는 이유만으로 전체 자동 재실행이 되는 것은 아니다. 기존 공동 DB에 무단 재적재하지 않는다.

### 4.3 시연 B — 실제 그래프 조회

[Text2Cypher 노트북](../../notebooks/respiratory/text2cypher_demo.ipynb)을 `.venv` 커널로 열고 연결 셀 실행 → 질문 → Cypher 생성 → 실행 전 검사 → 조회 실행 → 검증된 동일 쿼리를 Aura Query에 복사한다. [사용법](../../notebooks/respiratory/Text2Cypher_시연_사용법.md)을 따른다.

대표 검증 질문: **“보호자 연락 행동과 근거 문서를 그래프로 보여줘”**. 11/9 기록은 8경로·3문서이며 송수림이 같은 프로젝트 Aura 화면에서 문서 3·행동 8·개념 1을 확인했다. Text2Cypher는 메인 서비스와 분리된 시연이며 Citation을 대신하지 않는다. 생성 결과 변동·0건·거부를 구분하고, VALID가 질문 의미의 완전한 정답을 보장하지 않음을 설명한다.
