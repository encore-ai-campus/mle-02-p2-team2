# school 임시 표준 사전

공통 사전(`data/specs/ids/`)이 3인 승인되기 전까지 school 파이프라인이 쓰는 **개인 임시 사전**이다. 팀 개발 지시서 v1.2 §5 "공통 파일 대기 없이 시작하는 방법"에 따라 school 개인 경로에 둔다.

| 파일 | 내용 | 기준 |
|---|---|---|
| `diseases.json` | Disease 11종, 별칭, 넓은 표현(`review_aliases`) | 온톨로지 v3.1 4절 ③ + 두 학교 문서의 표기 |
| `roles.json` | SchoolRole 11종, 별칭, 복합 표기·제외 표기·미등록 표기 | 온톨로지 v3.1 4절 ④ + 두 학교 문서 역할표 |
| `concepts.json` | ActionConcept 27개, 신고·보고 구분 설명, 신규 개념 후보 | 온톨로지 v3.1 7절 + 11/3 추출 후보 |
| `__init__.py` | 읽기·무결성 검사·Neo4j 적재 속성 추리기 | 수업 42-5 normalize/rule_link (R03) |

## 사용법

```python
from index.school.dictionaries import load_dictionaries, alias_index, compare_key

books = load_dictionaries()          # 검사 실패 시 DictionaryError
roles = alias_index(books["role"]["entries"], "role_id")
roles[compare_key("보건 (담당) 교사")]   # 'HEALTH_TEACHER'
```

## 규칙

- **확정 연결은 `name`과 `aliases`의 유일한 일치만** 쓴다. `review_aliases`, `compound_mentions`, `unregistered_mentions`는 자동 연결하지 않고 검수로 넘긴다. `excluded_mentions`(보건소·교육청·보호자 등)는 SchoolRole을 만들지 않는다.
- `pending_candidates`는 표준 ID가 아니다. 3인 승인 전에는 `INSTANCE_OF`를 만들지 않는다.
- Neo4j에는 온톨로지 속성(`*_id`, `name`, `aliases`; 개념은 `concept_id`, `name`)만 적재한다. `evidence`·`note`·`group`은 검수용이다.
- 공통 사전이 승인되면 이 폴더의 JSON을 `data/specs/ids/`로 옮기거나 공통 로더로 교체하고, 차이가 있으면 기록한다.
