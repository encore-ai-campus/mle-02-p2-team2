# 제약조건·인덱스 기준 (우리 기준, 2026-11-05)

> 회의 결정 1번·8번: 제약조건·인덱스는 **우리가 정한 기준으로 통합**하고, 필요하면 우리가 만든다.
> 기준은 온톨로지 v3.1과 공통계약 v2.0을 따른다. 이 기준에 없는 제약·인덱스는 만들기 전에 이 문서에 먼저 적는다.

## 1. 제약조건 (고유성) — 현재 6개, 모두 있음

| 라벨 | 속성 | 이유 | 현재 |
|---|---|---|---|
| Document | document_id | 문서 식별 (`발행처_약칭_판본`) | 있음 |
| Chunk | chunk_id | 원문 조각 식별 (문단 `b` 형식, 표 행 `t{표}r{행}` 형식 모두 포함) | 있음 |
| SchoolAction | action_id | 행동 식별 | 있음 |
| SchoolRole | role_id | 역할 식별 | 있음 |
| Disease | disease_id | 질병 식별 | 있음 |
| ActionConcept | concept_id | 행동 개념 식별 | 있음 |

- 추가할 제약은 지금 없다. 새 라벨을 만들 때 같은 방식으로 고유 ID 제약을 먼저 만든다.

## 2. 인덱스

| 이름 | 종류 | 대상 | 설정 | 기준 | 현재 |
|---|---|---|---|---|---|
| chunk_text | 전문 검색 | Chunk.text | 분석기 `cjk` | 한국어 전문 검색 (수업 38-1) | 있음 · cjk 일치 |
| chunk_embedding | 벡터 | Chunk.embedding | 1536차원, 코사인 | 임베딩 small3 (1536차원) | 있음 · 차원·유사도 일치 |
| action_stage | 범위 | SchoolAction.stage | 기본 | 단계 필터 (온톨로지 v3.1 5-3 초안) | 있음 |
| action_scope | 범위 | SchoolAction.scope | 기본 | 범위 필터 (온톨로지 v3.1 5-3 초안) | 있음 |
| action_id, role_id, concept_id, disease_id, document_id, chunk_id | 범위 | 각 ID | 기본 | 제약과 같은 이름의 조회 인덱스 | 있음 |

- **추가로 만들 인덱스는 지금 없다.** 필요가 생기면 다음 순서로 한다: 이 문서에 이름·대상·이유 기록 → 테스트 DB에서 먼저 확인 → 공동 DB에 생성 → 이 문서에 완료 날짜 기록.
- 같은 이름의 인덱스가 있으면 `IF NOT EXISTS`가 설정을 바꿔 주지 않으므로, 설정이 다르면 만들지 않고 기록한다.

## 3. 적용 규칙
- 테스트 데이터는 `PLTest` 라벨과 `test_` 접두사로만 만든다. 테스트용 제약·인덱스는 만들지 않는다.
- 공동 DB 적재는 최종 결과가 나온 뒤에 한다 (회의 결정 2번).
- 임베딩 차원을 바꾸면 벡터 인덱스를 다시 만들어야 하므로, 모델을 바꾸기 전에 이 문서를 먼저 고친다.

## 4. 확인 결과 (2026-11-05, 읽기 전용)
- 제약 6개: 기준과 일치
- 전문 검색 `chunk_text`: cjk, 기준과 일치
- 벡터 `chunk_embedding`: 1536차원, 코사인, 기준과 일치
- `action_stage`, `action_scope`: 온톨로지 v3.1 초안에 이름까지 적힌 인덱스이며 DB에 있음
- `basis` 인덱스: 온톨로지 v3.1 초안에 없으므로 만들지 않음
- 임베딩 `small3` = `text-embedding-3-small` (팀 코드 `src/index/school/embed.py`, 1536차원). 벡터 인덱스 1536과 일치
- 벡터 인덱스는 팀 합의 임베딩(1536)에 맞춰 만들어졌으므로 차원 변경 시 인덱스를 다시 만든다
- 전문 검색 `cjk`는 온톨로지 v3.1에 분석기가 명시되지 않은 우리 선택(수업 38-1 기준)
- **결론: 새로 만들 제약·인덱스 없음. 기준과 DB가 일치함.**
