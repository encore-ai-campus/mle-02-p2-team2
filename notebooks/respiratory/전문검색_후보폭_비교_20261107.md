# 전문검색 중간 후보 수 비교 — 2026-11-07

## 실험 조건

최종 인용은 기본 8개로 고정하고, Neo4j 전문검색과 직접 후보를 사용하는 중간 검색 후보 수를 32·48·64로 바꾸었다. `embedder=None`이므로 벡터 검색·외부 AI 호출은 없다. 실행 시 DB의 전체 문서를 허용했고 질병 질문 10개를 각 설정에서 순차 실행했다. R-Q3에는 새 직접 근거 121쪽을 추가 관찰했다. ([재현 코드](golden_fulltext_width_check.py), [결과](golden_fulltext_width_20261107.json))

같은 골든 질문을 사용한 탐색이며 DB가 고정된 엄밀한 실험이나 별도 미사용 평가셋이 아니다. 121쪽은 manifest 선정 범위 밖이다. 페이지 순위는 해당 문서·PDF 쪽에 해당하는 Citation의 위치이며, 답변 의미의 정답성까지 증명하지 않는다.

이 결과 저장 후 공통 골든 스크립트에 R-Q3의 세 직접 근거와 `best_direct_rank`를 명시했다. 이 실험에서는 이미 121쪽을 별도로 관찰했으며, 결과 JSON의 해시는 실행 당시 코드 상태를 보존한다.

## 관찰 결과

나머지 7개 질문에서 이 실험이 관찰한 정답 문서·쪽의 순위는 세 설정 간 같았다. 그중 R-Q2와 R-T1은 각 기대 쪽이 세 설정에서 모두 8개 밖이므로 순위가 같다는 말이 품질이 충분하다는 뜻은 아니다. 30개 실행 모두 Citation·Finding·GraphPath의 확인된 DB 대조 오류는 없었다.

## 판단

후보 48개에서 두 질문은 좋아졌지만 R-Q3의 직접 근거 누락은 해결되지 않았다. 이 실험만으로는 후보 수를 늘리는 것이 실제 벡터 결합 검색에서 유효하거나 다른 질문에서 안전하다고 결론 낼 수 없다. 특히 R-Q3 118쪽은 이전 단계 추적에서 질병명과 ABOUT 관계가 없어 후보에 들어와도 질병 필터를 통과하지 못하는 문제가 별도로 있었다. 기존 검색 기본값은 이 실험을 근거로 바꾸지 않았다.

벡터를 포함한 실제 설정의 비교는 외부 AI 전송을 포함할 수 있어 명시적 승인 없이 실행하지 않았다. 사용자가 중단했던 [이전 후보폭 실험](golden_candidate_width_20261106.json)은 결과 없음으로 보존한다.
