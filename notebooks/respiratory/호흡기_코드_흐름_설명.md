# 호흡기 담당 코드 흐름 — 처음 보는 사람을 위한 안내

## 먼저 큰 그림

이 프로젝트에는 **문서를 미리 준비하는 과정**과 **질문이 들어왔을 때 찾는 과정**이 있다. 둘을 구별하면 코드의 역할을 이해하기 쉽다.

```text
[미리 준비]
지침 Markdown → 청크 → AI 행동 후보 → 원문 대조·검수 → 적재 패키지 → Neo4j

[질문할 때]
Streamlit 질문 → 메인 그래프가 Tool 선택 → Neo4j에서 근거 검색 → 답변·출처 표시
```

PDF 원본을 그대로 DB에 넣어 답을 생성하는 방식이 아니다. 이 저장소의 호흡기 전처리는 PDF에서 변환된 Markdown을 읽는다. 사용자가 확인할 수 있도록 문서 ID·PDF 쪽수·청크 ID를 함께 보존한다.

## 1. 원문을 청크로 만들기

**파일:** [md_to_blocks.py](../../src/preprocess/respiratory/md_to_blocks.py)

- `clean_page()`는 페이지 안에서 보존용 원문이 있으면 그 부분을 쓰고 이미지 링크·주석 등 표시를 정리한다.
- `main()`은 문서 ID와 PDF 페이지를 확인한 뒤, 내용이 있는 각 페이지에 `문서ID:p쪽:b01` 형식의 청크 ID를 붙여 로컬 `data/interim/respiratory/blocks.jsonl`에 저장한다.
- `pdf_page`는 PDF 뷰어의 쪽이고 `printed_page`는 책에 인쇄된 쪽이다. 예를 들어 인플루엔자 PDF 17쪽은 인쇄 13쪽이다.
- **왜 나누나?** 긴 문서 전체를 답변에 넣는 대신 필요한 부분을 찾고, 나중에 어느 문서의 몇 쪽인지 되짚기 위해서다.
- 현재 기본 청크는 페이지 단위다. 새 [table_rows.py](../../src/preprocess/respiratory/table_rows.py)는 표를 행별 검수 후보로 만드는 별도 준비 코드이며 기존 DB에는 적용되지 않았다.

## 2. 학교 행동 후보 추출

**파일:** [extractor.py](../../src/index/respiratory/extractor.py), [v0 프롬프트](../../src/index/respiratory/prompts/v0_school_action.md), [v1 프롬프트](../../src/index/respiratory/prompts/v1_school_action.md)

- `select_blocks()`는 문서 ID와 쪽으로 입력 청크를 고른다. `call_model()`은 선택 청크와 지침을 AI에 보내 행동 후보를 JSON으로 받는다.
- 각 후보는 행동 문장뿐 아니라 원문 근거, 적용 조건·기한, 질병, 역할, 행동 개념 등을 가진다. 모델 응답은 **후보**이며 사람의 검수와 같다거나 정답이라고 가정하지 않는다.
- `validate_action()`은 필수 항목·허용값·인용 문구가 원문에 있는지 점검한다. `validate_block_action()`은 표 행의 경우 근거가 제목만이 아니라 데이터 행에 있는지도 점검한다.
- v1은 표의 행·머리글을 혼동하지 않도록 지침을 추가한 버전이다. 기본값은 v0이다. 표 행을 별도 결과 파일로 전달하는 연결은 가상 모델로 검증했지만 실제 AI 재추출은 하지 않았다.
- **주의:** 추출기 실행은 문서 텍스트를 외부 AI에 보내고 로컬 결과 파일을 바꿀 수 있다. 작성된 프롬프트와 실제 재추출 완료는 다르다.

## 3. 정규화와 검수

**파일:** [normalize.py](../../src/index/respiratory/normalize.py)

- `normalize_row()`는 추출 후보를 복사하고, `REVIEW_DECISIONS`에 기록된 사람의 검토 결정과 원문·ID·허용값 검사를 반영한다.
- 문제가 없고 승인 결정이 있으면 `APPROVED`, 제외 결정이면 `EXCLUDED`, 검토가 없거나 문제가 남으면 `PENDING`이다.
- **왜 필요한가?** 같은 역할·질병을 사전에 맞춰 쓰고, 원문에 없는 행동이나 근거를 그대로 DB에 넣지 않기 위해서다. 코드 검사가 모든 의미 오류까지 잡는 것은 아니므로 사람의 원문 검토가 필요하다.
- 저장된 정규화 결과의 한 예: 인플루엔자 PDF 17쪽 행동 `kdca_flu_facility_2026:p0017:a04`는 `CONTACT_GUARDIAN`으로 검토됐고, 근거는 `...:p0017:b01`이다. `done_by=[]`는 구체적인 학교 역할 관계를 만들 근거가 없다는 뜻이지, 아무도 그 행동을 하지 않는다는 뜻은 아니다.

## 4. Neo4j에 넣을 패키지 만들기

**파일:** [load.py](../../src/index/respiratory/load.py), [공통 bundle 검사](../../src/index/school/bundle.py)

- `make_inputs()`는 검수 상태가 `APPROVED`이고 문제가 없는 행동만 모은다. 원문 청크는 별도로 가져온다.
- `make_bundle()`은 Document·Chunk·SchoolAction과 관계를 공통 형식으로 조립하고 구조를 검사한다. 호흡기 적재 범위를 담당 문서 3종으로 제한하는 검사도 있다.
- `--check-db`는 DB 상태를 읽는다. `--apply`는 DB에 쓰며, `--embed`는 임베딩을 만들고 적재한다. 기본 실행도 로컬 `bundle.json`을 쓰므로 아무 옵션 없이 실행해도 완전한 읽기 전용은 아니다.
- **왜 Neo4j인가?** 문서에서 나온 행동과 원문 근거, 질병·역할·공통 개념을 관계로 연결해 출처를 따라가고 문서 간 같은 행동을 비교할 수 있기 때문이다.

## 5. 질문이 들어오면

**질병 사실:** [disease_tool.py](../../src/rag/respiratory/disease_tool.py)

1. 질문에서 질병명·별칭과 핵심어를 확인하고 허용 문서 범위를 적용한다.
2. 전문검색과 벡터검색 결과를 합치고, 질병명과 핵심어에 직접 맞는 후보도 찾는다.
3. 머리말·제외 문구·질병 및 핵심어 일치 등을 확인하고, 선택한 청크와 PDF 쪽을 Citation으로 반환한다.
4. 전문검색은 단어가 일치하는 문장을 찾고, 벡터검색은 질문과 의미가 가까운 문장을 찾는 데 쓰인다. 둘을 합쳐도 올바른 순위가 보장되지는 않는다.

**여러 문서의 행동 비교:** [crossdoc_tool.py](../../src/rag/respiratory/crossdoc_tool.py)

1. 예를 들어 ‘보호자 연락’을 공통 개념 `CONTACT_GUARDIAN`에 연결한다.
2. 그 개념에 연결된 각 문서의 행동을 찾고, 행동에서 원문 청크·문서·확인된 역할로 관계를 따라간다.
3. 문서별 Citation과 **실제로 조회한 관계의 경로(GraphPath)**를 반환한다. 담당 역할 관계가 없으면 없는 대로 표시한다.

**화면 연결:** [UI service.py](../../src/rag/ui/service.py)는 Tool들을 등록하고 메인 그래프를 호출한다. 다만 현재 일반 화면의 기본 허용 문서에는 호흡기 담당 3종이 포함되지 않아 담당자 확인이 필요하다. 가상 화면 시험은 통과했지만 실DB·외부 AI를 함께 쓰는 화면 시험은 아직 하지 못했다.

## 6. R-Q3를 예로 보면

질문은 ‘성홍열 진단 학생의 등교중지 기준은?’이다. PDF 116·118·121쪽은 각각 해당 기준을 직접 설명한다. 그러나 현 검색에서는 118쪽 청크가 본문에 성홍열 이름을 갖고 있지 않고 ABOUT 관계도 없어 질병 근거를 인식하지 못할 수 있다. 문서에 답이 있어도 **어떻게 나누고 어떤 맥락을 보존했는지**에 따라 검색 결과가 달라진다는 사례다. ([원문·검색 단계 기록](오늘_진행_20261106.md), [골든 근거](../../data/specs/golden/respiratory.md))

## 7. 발표에서 말할 수 있는 핵심

> “호흡기 지침을 PDF 쪽 단위 청크로 만들고, 학교 행동 후보를 추출한 뒤 원문과 허용값을 검토했습니다. 승인된 행동과 출처를 Neo4j에 연결하고, 질병 질문은 문서 근거를 검색하며, 문서 비교 질문은 공통 행동 개념을 따라 실제 관계와 출처를 반환합니다. 표 행 분리와 일부 검색 누락은 현재 검증·개선 중입니다.”

이 문장은 현재 기록된 범위의 설명이다. DB에 반영되지 않은 표 행이나 코로나19 학교 행동 추출을 완료했다고 말하지 않는다.
