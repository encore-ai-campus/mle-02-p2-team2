## 보관 자료와 검사

- 파일: 로컬 전용 `notebooks/respiratory/backups/neo4j_readonly_20261106T174501Z.jsonl.gz`. 파일 이름 시각은 UTC이며 한국 시각으로 2026-11-07 02:45:01이다.
- 원문·임베딩을 포함하므로 `backups/.gitignore`로 해당 폴더 내용을 제외하고 파일 권한을 소유자 읽기·쓰기(0600)로 설정했다. Git 명령·커밋·업로드는 실행하지 않았다.
- 크기: 12,631,476 bytes. SHA-256: `482d94f912103efa5940d69c60a39e6568d84aee4032c75913beba2469522096`.
- Neo4j 읽기 트랜잭션에서 노드·관계·속성과 인덱스·제약 메타데이터를 내보냈다. 노드 2,250·관계 3,069, 제약 6·인덱스 12였고, 인덱스 12개 상태는 ONLINE이었다.
- gzip을 다시 읽어 노드 중복 식별자, 모든 관계의 양 끝, 마지막 레코드의 개수를 확인했다. Chunk 1,731개의 임베딩이 모두 보존됐고 각 차원은 1,536이었다. 내보내기 중 조회한 DB 노드·관계 개수와도 일치했다.
- [백업 코드](backup_readonly.py)는 읽기 전용 세션을 사용하고 같은 파일을 덮어쓰지 않는다. 가짜 DB로 백업·덮어쓰기 방지·끝점 누락 검증을 검사했다.

## 한계와 후속

이 파일은 Neo4j의 서버 측 `dump`가 아니라 데이터·메타데이터의 gzip JSONL 내보내기다. `elementId`는 이 백업 안에서 관계 끝점을 이어 주는 임시 식별자이며 복구 후에도 유지된다고 가정하지 않는다. 백업과 내보내기 중 노드·관계 수가 같더라도 읽기 격리 방식상 팀원의 동시 변경이 전혀 없었다고 보장하지 않는다.

실제 복원 코드·격리 환경에서의 복원 시험·복원된 인덱스 설정 및 검색 결과 비교는 수행하지 않았다. 따라서 **복구가 검증된 백업은 아니다.** 복원 시에는 안정적인 문서·청크·행동·사전 ID로 노드와 관계를 다시 매핑하고, 제약·인덱스 및 임베딩과 샘플 질의를 검증해야 한다. 복원은 DB 쓰기이므로 별도 승인 전에는 실행하지 않는다.
