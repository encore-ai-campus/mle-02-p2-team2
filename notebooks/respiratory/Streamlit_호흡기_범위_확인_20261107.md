# Streamlit 기본 검색 범위에서 호흡기 문서 누락

## 확인한 사실

[UI service.py](../../src/rag/ui/service.py)의 `EVALUATED_DOCUMENTS`에는 학교·홍역·진단·법령 문서 5개가 있고 호흡기 담당 문서 3개가 없다. [app.py](../../src/rag/ui/app.py)의 일반 사용자 화면은 이 목록에서 실제 DB에 있는 문서만 `allowed_document_ids`로 선택한다. 개발자 화면에서만 목록을 바꿀 수 있다.

가짜 문서 목록·가짜 답변을 넣은 Streamlit AppTest에서 화면은 열리고 질문·가상 답변이 표시됐으며, 일반 사용자 기본 허용 목록에 아래 3문서는 없었다. 이 실험은 실제 DB·실제 답변 검증이 아니다.

```text
kdca_respiratory_2026
kdca_flu_facility_2026
kdca_covid19_2026
```

## 영향과 제안

일반 사용자 화면에서는 세 문서가 DB에 있어도 검색 도구에 허용 문서로 전달되지 않는다. 같은 질병에 대한 다른 허용 문서의 근거는 반환될 수 있으므로, 모든 질병 질문이 반드시 실패한다고 단정하지 않는다. 호흡기 원문에 대한 시연은 이 설정을 해결해야 한다.

담당자 검토안: 기본 허용 문서에 위 세 document_id를 추가한다. 문서를 추가하면 검색 범위와 답변이 바뀔 수 있으므로 다음을 확인한다.

1. DB에 실제 존재하는 문서만 선택하는 기존 조건과 빈 허용 목록 동작이 유지되는지.
2. 인플루엔자·성홍열·코로나19 대표 질문이 일반 화면에서 실제 담당 문서를 인용하는지.
3. 기존 학교 행동·법령·문서 비교 질문의 인용과 답변이 나빠지지 않는지.
4. 선정 페이지·판본과 출처 URL이 일치하는지. 특히 [호흡기 판본 URL 차이](기획배경_문서판본_20261107.md)와 121쪽 선정 범위를 먼저 고려한다.

UI는 다른 담당자 영역이므로 이 검토안 작성 시 UI 코드는 수정하지 않았다. 실DB·외부 AI를 함께 쓰는 화면 시험은 자동 승인 심사에서 질문·DB 근거의 외부 전송에 대한 명시적 승인 부재로 거절돼 실행하지 못했다. 이후 외부 AI를 끄도록 준비한 실DB 화면 시험도, 심사에서 앱의 환경 설정 경로를 통한 외부 전송 가능성을 배제할 수 없다는 이유로 거절돼 실행하지 못했다. 심사 결정을 우회하지 않았다.
