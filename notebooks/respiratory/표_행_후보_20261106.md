# 표 행 청크 후보 — 2026-11-06

## 목적과 현재 상태

공통 온톨로지의 표 행 단위 규칙을 호흡기 지침에 적용하기 위해 [후보 생성 코드](../../src/preprocess/respiratory/table_rows.py)를 만들었다. 입력 Markdown은 읽기만 하며 기존 `blocks.jsonl`·골든 인용·Neo4j를 바꾸지 않는다. 후보는 아직 정식 청크나 DB 적재물로 승인된 것이 아니다.

표마다 데이터 행을 나누고, 한 행의 후보에 현재 페이지에서 읽은 제목·열 머리글·행을 함께 넣는다. ID는 공통 `document:pNNNN:tNNrNN` 규칙을 쓴다. 제목은 변환본의 가까운 제목이므로 실제 PDF 표 제목과 같은지 수동 확인이 필요하다. 빈 셀·열 수 불일치·HTML 표·1열 표 등은 조용히 해석하지 않고 검수 표시 또는 미처리 경고를 남긴다. 셀 병합 구조를 자동 복원하지 않는다.

| 호흡기감염병 | 0 | 0 | Markdown 파이프 표로 인식된 것이 없다는 뜻; 원본에 표가 없다는 뜻은 아님 |

코로나19 PDF 39쪽의 ‘잠복기’ 행은 후보 ID `kdca_covid19_2026:p0039:t01r06`으로 생성됐다. 기존 골든과 DB는 페이지 청크 `kdca_covid19_2026:p0039:b01`을 가리키므로, 나중에 전환하려면 인용·행동 관계·임베딩의 영향 검토가 필요하다. 행 번호와 제목은 PDF 원본 검수 전 확정하지 않는다.

현재 manifest의 코로나19 선정 쪽은 PDF 28쪽이며 위 124개 행 후보는 이 범위에 없다. DB에는 39쪽의 기존 페이지 청크가 있어 선정 범위와 실제 데이터 범위도 맞춰야 한다. 전 범위 후보 수를 선정 범위의 완료 수로 쓰지 않는다.

## 검사와 남은 일

- 새 테스트는 행 ID·제목/머리글 보존, 빈 셀과 잘못된 열 수, HTML 표 경고, 쪽별 ID와 이스케이프 파이프를 확인했다. 호흡기 전처리·호흡기 검색·학교 검색·UI 테스트 합계 **303 passed, 9 skipped**. 변경 Python 파일 `ruff check` 통과.
- 표가 Markdown으로 변환되지 않은 호흡기·인플루엔자 쪽은 PDF 원본 또는 구조화된 표 작업본 확인이 필요하다. 변환본에서 찾지 못한 표를 임의 생성하지 않는다.
- [프롬프트 v1](../../src/index/respiratory/prompts/v1_school_action.md)을 추가했다. 행 인용은 해당 행의 연속 원문만 쓰고, 제목·머리글은 맥락으로만 사용하며, 빈 셀과 다른 행의 내용을 추측하지 않도록 명시했다. 추출기는 `--table-rows --prompt-version v1 --candidate-output 새_파일.jsonl`을 명시하면 변환 Markdown에서 행 후보를 읽도록 연결했다. 이 경우 출력은 `notebooks/respiratory/` 안의 아직 없는 JSONL이어야 하며, 기존 결과를 덮어쓰지 않는다. action ID는 임시이며 모델 응답은 PENDING이다. 기본 입력과 프롬프트는 이전과 같다.
- 추출·정규화 검사는 표 행의 인용이 제목이나 머리글이 아니라 해당 `row_text`에 있어야 한다. 행 원문 누락 또는 `review_flags`가 있으면 검수 사유로 남아 승인되지 않는다. 이 검사가 모델 호출을 대신하지는 않는다. ([추출기](../../src/index/respiratory/extractor.py), [정규화](../../src/index/respiratory/normalize.py))
- 가상 모델로 표 행 입력부터 별도 파일의 PENDING 후보 출력까지 연결하고 기존 파일이 보존되는지 시험했다. 프롬프트·표 인용 및 정규화 검사를 포함해 호흡기 index·preprocess·rag와 학교 검색·UI 테스트 **315 passed, 9 skipped**, 관련 코드 `ruff check` 통과. 외부 AI를 사용한 실제 재추출·PDF 원문 검수·행 ID 이행과 실DB 반영은 수행하지 않았다. 기존 인용을 변경하기 전 영향과 복구 방법을 확인해야 하며 현재 DB 쓰기는 금지다.
- 이후 2026-11-07 전체 `uv run pytest tests -q`는 **340 passed, 10 skipped**였다. 자동 테스트 범위로서 실모델·실UI·DB 재적재 검증과 구분한다.
