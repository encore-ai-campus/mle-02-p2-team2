# 질문 입력 → Cypher → 프로젝트 Aura 그래프 시연

11/9 구현. 운영 검색 Tool·메인 LangGraph·DB 데이터·스키마는 변경하지 않았다.

## 실행할 파일

- [text2cypher_demo.ipynb](text2cypher_demo.ipynb): 질문 자유 입력, 실제 스키마 확인, 생성·검사·실행 버튼, Aura 복사용 쿼리.
- [text2cypher_demo.py](text2cypher_demo.py): 연결·스키마 수집·생성·검사·읽기 실행·Path 보존·안전한 표시.
- [text2cypher_schema.json](text2cypher_schema.json): 관찰 시각·인스턴스 지문·DB 이름·구조·값 사전·의미 규칙·명세 차이.
- [text2cypher_evaluate.py](text2cypher_evaluate.py): 정해 둔 8문항과 기존 3개 고정 조회 결과를 비교하는 실행 코드.
- [text2cypher_eval.jsonl](text2cypher_eval.jsonl), [평가 요약](text2cypher_eval_summary.json): 실제 생성문·실행문·검사·지연·비교·실패 기록.

## 연결과 계정

저장소 루트의 `.env`에서 기존 프로젝트 `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`, `NEO4J_DATABASE`를 읽는다. URI·계정명·비밀번호·API 키는 출력하거나 산출물에 저장하지 않는다. 프로젝트 Aura의 인증서 검증 TLS 주소를 그대로 사용하며 로컬 DB를 만들지 않는다.

**계정 조건 변경:** 원 지시서는 읽기 전용 계정을 요구했지만, 11/9 사용자가 기존 계정 사용을 요청했다. 현재 계정에는 관리자용 역할이 있으며 DB 계정 자체의 읽기 전용 권한은 확인되지 않았다. `READ_ACCESS`는 쓰기 권한을 없애지 않는다. 이번 구현은 프로그램의 검사로 읽기만 허용하며 이 차이를 스키마·평가 요약에 남겼다. 별도 읽기 계정을 이미 보유한 경우 `NEO4J_READONLY_USERNAME`·`NEO4J_READONLY_PASSWORD`를 설정하면 우선 사용한다. 구현 코드에서 계정·권한을 생성·변경하지 않는다.

모델은 `TEXT2CYPHER_MODEL`, 기존 `SCHOOL_RERANK_MODEL`, 기본 `gpt-6-luna` 순서로 선택한다. 실제 사용 모델·패키지 버전은 평가 기록에 남는다. LLM에 보내는 것은 질문·구조·작은 값 사전·예시이며, DB 조회 결과·전체 원문·embedding·접속 정보는 보내지 않는다.

접근 범위는 프로젝트 Aura의 현재 Document 전체 10개다. 문서별 접근 제한을 프롬프트로 구현했다고 보고하지 않는다.

## 노트북 실행 순서

1. VS Code에서 `text2cypher_demo.ipynb`를 열고 프로젝트 `.venv`의 Python 커널을 선택한다. 현재 환경에는 neo4j·langchain-openai·ipywidgets·nbformat·nbclient·ipykernel이 설치돼 있어 추가 설치하지 않았다.
2. 위에서부터 연결 셀을 실행한다. `connected: 1`, 인스턴스 지문, 선택 DB, 접근 문서 목록, 계정 확인 상태를 본다. 비밀 URI 대신 별칭과 지문을 기록한다.
3. 스키마 펼침 항목에서 관찰된 노드·관계 방향·질병/역할/개념/문서 ID와 별칭을 확인한다. 속성 목록은 합집합이며 모든 노드가 모든 속성을 갖는다는 뜻은 아니다.
4. 질문을 자유롭게 입력하고 **1. Cypher 생성**을 누른다. 이 단계는 LLM만 호출한다. 생성문을 화면에서 확인한다.
5. **2. 실행 전 검사**를 누른다. 결과가 `VALID`일 때만 실행 버튼과 Aura 복사란이 준비된다. 쿼리·질문 편집 시 기존 검사는 무효가 된다.
6. **3. 조회 실행**을 누른다. 검사된 동일 문자열을 실행하고 원시 Record·Path는 `raw_records`에 보존한다. DB 실행 단계에서 LLM을 다시 호출하지 않는다.
7. 집계는 표 형태의 JSON 값으로 본다. 그래프는 노드·관계·방향·문서·PDF 쪽수와 200자 이내 원문 표시를 확인한다. 그래프 원시 객체를 곧바로 `record.data()`나 문자열로 바꾸지 않는다.
8. 아래 Aura 화면 절차로 같은 쿼리의 실제 그래프를 확인한다. 종료 셀의 `close_connection=True`는 시연을 마쳤을 때만 실행한다.

일반적인 노트북 전체 셀 실행은 모델을 자동 호출하지 않는다. 자유 입력의 생성 버튼을 누를 때 호출한다. 자동 검증용 `TEXT2CYPHER_NOTEBOOK_SMOKE=1` 모드에서만 UI 콜백을 실제로 한 번 호출하며, 평가 8문항과 별도 기록이다.

## Aura의 그래프 화면에서 확인

1. 팀 Aura 콘솔에서 프로젝트 인스턴스를 선택한다. 개인 Aura나 로컬 DB를 선택하지 않는다.
2. 해당 인스턴스의 **Query 화면**을 연다. 11/9 10:01 송수림이 같은 프로젝트 Aura 인스턴스에서 E01을 실행하고 그래프 보기로 확인했다. [확인 캡처](captures/t2c_contact_guardian.png)
3. 노트북과 같은 데이터베이스를 선택한다. Python의 인스턴스 지문과 DB 이름을 참고해 연결 대상을 대조한다.
4. 노트북의 **Aura 복사**란에 있는 검증된 Cypher를 그대로 붙여 실행한다. 누락된 Python 변수나 별도 파라미터 설정은 없다.
5. `RETURN path` 질의는 그래프 보기, 집계는 표 보기를 선택한다. Python에서 조회했다고 Aura 웹 화면이 자동으로 바뀌지는 않는다.
6. Document·Chunk를 눌러 document_id·pdf_page·printed_page·text를 확인하고, 관계의 화살표·타입과 DONE_BY의 basis를 본다.
7. 쿼리를 수정했다면 원본을 보존하고 Python에서도 그 수정문을 재검사한다. 수정 전후 문자열을 평가 기록에 남긴다.
8. 실제 화면에서 확인한 뒤에만 노트북 마지막의 같은 인스턴스·동일 쿼리·그래프 확인란을 체크하고 관찰한 행 수를 입력한다. 저장되는 증빙은 `USER_CONFIRMED`인 사용자 수동 확인이며 자동 화면 검증이 아니다.

기본 보호자 연락 그래프의 실행 결과는 8경로다. 기존 터미널 도구의 8개 표 행을 8개 노드라고 해석하면 안 된다. 한 경로에는 문서·청크·행동·개념의 여러 노드와 관계가 들어 있다.

## 실행 전 검사와 한계

- 다중 문장·쓰기·관리 구문·프로시저·이름공간 함수·외부 접근을 거부한다. CALL은 읽기 서브쿼리만 허용하며 UNION을 지원한다. 지원 함수 목록은 소스의 `FUNCTIONS`에 명시돼 있다.
- 실제 스키마의 라벨·관계와 값 사전을 사용한다. 없는 ID는 `UNSUPPORTED`로 처리한다.
- EXPLAIN의 `query_type == 'r'`와 곱집합 실행 계획 여부를 확인한다. 실행 직전에 같은 쿼리를 다시 검사한다. 금지어 검사만으로 읽기 여부를 판단하지 않는다.
- 명시적 최종 LIMIT 50 이하가 필요하다. LIMIT을 자동으로 덧붙이거나 바꿔 UNION 의미를 변경하지 않는다. 무제한 경로·3홉 초과 가변 경로는 거부한다.
- 연결 대기와 DB 트랜잭션은 10초, 모델 호출은 30초 제한을 설정했다. 최종 LIMIT만으로 내부 집계·탐색 비용이 제한되는 것은 아니다.
- 표시 상한은 50행·100노드·150관계다. 한도에 닿으면 잘림 가능성을 기록하며 전체 정답이라고 설명하지 않는다.
- 설치된 Neo4j 드라이버는 managed transaction의 `tx.run(Query)`를 거부하므로 `Query.text`를 실행하고 timeout은 `unit_of_work`에 전달한다.
- `neo4j-graphrag`는 현재 프로젝트에 설치돼 있지 않다. 패키지를 추가하지 않고 제공된 수업의 생성→EXPLAIN→읽기 판정→실행 흐름을 분리 적용했다. `Text2CypherRetriever.search()`를 호출했다고 보고하지 않으며, 미설치 라이브러리의 시그니처를 지어내지 않는다.
- 생성 실패·검사 거부·구문 오류·시간 초과·조회 0건은 구별해 기록한다. 0건은 자료 전체에 해당 사실이 없다는 뜻이 아니다. Text2Cypher 결과는 Citation을 대신하지 않는다.

## 실제 실행 평가

8문항은 실행 전에 코드에 고정했으며, 결과를 본 뒤 정답 범위를 바꾸지 않았다. 별도 사람 판독은 미실시다. 새 질문 중 없는 대상·쓰기 요청은 거부 시험이므로 조회 정확도와 합산하지 않는다.

## 확인 상태

- 구현·실제 스키마 수집·LLM/DB 평가: 기록 확보.
- 기존 계정 사용: 사용자 요청 반영. DB 계정 자체의 읽기 전용 권한은 미확인/미충족으로 구분.
- 실제 Aura 웹 화면의 같은 프로젝트 인스턴스·DB·그래프 확인: **확인 완료**(2026-11-09 10:01 KST, 송수림 직접 실행). Query 화면에서 E01을 실행한 뒤 그래프 보기로 확인했다. [캡처](captures/t2c_contact_guardian.png)
- 확인 구성: 문서 3개(교육부 매뉴얼·경기도 가이드북·2026 인플루엔자 관리지침), SchoolAction 8개(교육부 4·경기 3·인플루엔자 1), ActionConcept 1개(개별 보호자 연락=CONTACT_GUARDIAN).
- 확인 방향: `Document-HAS_CHUNK->Chunk, SchoolAction-SUPPORTED_BY->Chunk, SchoolAction-INSTANCE_OF->ActionConcept`.
- 대조 방법: 표 화면의 행 수는 직접 확인하지 않았고, 그래프의 SchoolAction 노드 8개·문서 3개로 Python 결과 8행·3문서와 같음을 확인했다. 에이전트의 자동 화면 검증이 아닌 송수림의 직접 실행·사용자 보고다.

최종 검사: ruff 통과, `89 passed in 1.43s`. 최종 검사기로 저장된 생성문 8개를 재검사해 판정 8/8 유지(새 LLM 호출·조회 본문 실행 없음). 노트북 코드 셀 8개 오류 0·실제 UI 콜백 8행. [추가 단위 테스트](../../tests/rag/respiratory/test_text2cypher_demo.py).
