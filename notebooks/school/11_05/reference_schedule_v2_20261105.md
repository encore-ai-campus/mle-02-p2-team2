### 1-1. 기능 우선순위

| 우선순위 | 반드시 확보할 것 |
|---|---|
| **P0 — 수업 필수** | LLM 개체·관계 추출 프롬프트·코드·예시, Neo4j 스키마·적재 코드·Cypher·그래프 시각화, 원문 근거 |
| **P0 — v2.0 핵심** | 메인 LangGraph의 질문 분류/Tool 실행, Action/Disease/Legal 3개 Tool, Finding/Citation 검증 |
| **P0 — GraphRAG 시연** | **Action 관계 탐색 또는 CrossDoc 문서 횡단 탐색**의 실제 노드·관계·원문 경로 |
| **P1 — 중요** | CrossDocGraphTool, 조건부 추가 검색 및 종료, 골든 질문·UI·오류 경로 |
| **P2 — 선택** | 새로운 노드 종류, 복잡한 Text2Cypher, GDS, 전체 결핵 지침 적재, 11개 질병 전부 심층 자동화, 고급 UI |

**일정 조정 원칙:** P0와 검증된 시연을 우선 보존한다. P1이 늦어져도 억지로 기능을 붙이지 않고 가능한 범위를 정확히 설명한다.

**분업의 경계:** Tool 소유자는 검증된 코드를 메인 Graph가 import/호출 가능하게 전달한다. Tool 안에서 쓸 검색법, 로컬 State, 프롬프트·Cypher는 자유다. 팀원별 데이터 소유권은 공통 Neo4j의 **조회 제한이 아니다**. 메인 Graph에는 3명의 미완성 QueryGraph에 의존하는 경로를 남기지 않는다.

### 2-1. Tool별 전달 완료 조건(Definition of Done)

| 산출물 | 담당 | 필수 확인 내용 |
|---|---|---|
| `ActionSearchTool` | 주승우 | 병명 없는 학교 행동·역할 질문 1개 이상; **SchoolAction→DONE_BY→SchoolRole 및 SUPPORTED_BY→Chunk** 실제 조회; Finding/Citation |
| `DiseaseSearchTool` | 송수림 | 인플루엔자/성홍열 질병 사실 1개 이상; 관련 Chunk·Document 인용; 근거 없을 때 `NO_EVIDENCE` |
| `LegalSearchTool` | 유종혁 | 신고 기준·법령 1개 이상; 학교의 교육청 보고/학교장 신고/의료기관 신고 구분; 실제 근거 인용 |
| `CrossDocGraphTool` | 송수림 구현·공동 검증 | 같은 ActionConcept의 문서별 SchoolAction·Role·Chunk/Document 횡단 결과; `graph_paths` 실DB 검증 |
| 메인 LangGraph | 주승우 구현·공동 검증 | QueryInput→의도 분류→선택 Tool 호출→평가→QueryOutput; 추가 Tool 호출·호출한도·지원범위 분기 |
| 공통 계약 검증기 | 유종혁 중심·공동 승인 | ToolResult 키/상태, Finding↔Citation, 허용 문서 범위, 실제 ID/페이지 불일치 검출 |

**필수 완료 게이트:** 사용자 질문 1개 → 메인 LangGraph → **선택한 Tool 1개** → **공통 Neo4j** → **실제 Finding·Citation** → 응답까지 작동한다. Tool 3개도 각각 단독 호출된다.

**하지 않을 것:** 3개 QueryGraph 재구축, 전체 PDF 재적재, 11개 질병 전부 정밀 구축, 고급 UI 완성.

## 5. 11/08(일) 18:00 개발 동결 기준

아래 체크리스트는 **실제 실행 결과를 확인한 뒤** 완료 처리한다.

- [ ] 기존 3명의 데이터가 **하나의 공통 Neo4j**에 검증된 형태로 적재되어 있고 `Document`·`Chunk`·`SchoolAction` 출처 추적이 가능하다.
- [ ] 공통 ID·원문 페이지·`MERGE` 재적재 무중복 조건이 유지된다.
- [ ] 온톨로지 v3.1 승인 여부와 **실제 적용된 스키마 버전**이 기록되어 있다.
- [ ] 메인 LangGraph가 `QueryInput`을 받고 정상적으로 `QueryOutput`을 반환한다.
- [ ] `ActionSearchTool`, `DiseaseSearchTool`, `LegalSearchTool`이 **각각 독립적으로 호출**된다.
- [ ] `CrossDocGraphTool` 또는 Action Tool이 **실제 Neo4j 노드·관계 경로**를 반환하고 그 경로를 DB에서 검증했다.
- [ ] `ToolResult`가 공통 필드·상태·허용 문서 범위와 `Finding ↔ Citation` 검사를 통과한다.
- [ ] 단순 질문은 충분한 근거가 있을 때 **불필요한 Tool을 추가 호출하지 않는다**.
- [ ] 근거가 일부 부족한 질문은 다른 Tool을 **최대 총 3회 호출 한도 안에서** 검색하고 정상 종료한다.
- [ ] 지원 범위 밖의 의료·법적 판단을 **일반 LLM이 임의 확정하지 않는다**.
- [ ] 신고·보고 주체, 근거 없는 `SchoolAction`·잘못된 Citation과 같은 중대한 오류가 해결됐다.
- [ ] 골든 질문 10~15개를 검토하고 실패·제한사항을 기록했다.
- [ ] 단일 Q&A 화면, 실제 PDF 인용, Neo4j 관계 시각화/질의 결과를 확보했다.
- [ ] 코드·환경 설정 방법·DB·출력 JSON·발표 자료 및 예비 시연 캡처를 백업했다.

| 지연 또는 장애 상황 | 우선 대응 | 후순위로 내릴 것 |

**최소 성공 기준:** 검증된 공식 PDF를 단일 Neo4j에 적재하고, 메인 LangGraph가 질문을 분류해 적절한 Tool을 호출한 뒤 **실제 SchoolAction/SchoolRole/Chunk 또는 ActionConcept의 그래프 관계를 탐색하고 PDF Citation과 함께 답변**한다. 추가 Tool 재검색·문서 횡단 고도화는 가능하면 구현하되, 근거가 불충분하면 확인 필요로 명확히 표시한다.
