# 학교 담당 수업 코드 참고 패키지

이 자료는 원본 수업 폴더가 없는 프로젝트 작업자가 11월 4일 정규화·적재·질의 부품을 이해하도록 만든 개인 참고 패키지다. 수업 원본 발췌와 새로 작성한 학교 적용 예시를 함께 제공한다.

## 위치와 작업 범위

팀 개발 지시서 v1.2 §12-1의 주승우 개인 범위인 **기존 `notebooks/school/`** 안에 세 파일만 추가한다. 공용 docs 폴더나 하위 패키지를 새로 만들지 않는다.

| 파일 | 용도 |
|---|---|
| [school_learning_reference.ipynb](school_learning_reference.ipynb) | 수업 원본 코드·의존성·학교 예시·실행 확인 |
| 이 안내문 | 패키지의 범위, 읽는 순서와 실행 방식 |
| [오늘_정규화_적재_질의_부품지시서.md](오늘_정규화_적재_질의_부품지시서.md) | 참고 부품 번호와 연결된 실제 구현 요청 |

이번 추가는 기존 노트북, 팀 기준 문서, common 코드, 공통 사전, 환경·의존성·Git 설정을 변경하지 않는다. 기존 수정 사항과 섞어서 커밋하지 않는다. 패키지 자체가 커밋·푸시를 실행하지 않으며, 공유할 때는 팀의 현재 main 작업 규칙을 따른다.

파일명은 노트북에 영문 소문자·언더스코어, 문서에 한글을 사용한다. 별도 하위 폴더를 만들지 않아 폴더 초기화 파일도 추가하지 않는다.

## 실행과 출처

참고 노트북의 코드 셀은 Python 표준 라이브러리만 사용하고, 외부 파일·API·DB 연결 없이 인공 데이터를 메모리에서 처리한다. Jupyter에서 위부터 모두 실행하면 성공/실패 사례의 assert 검사를 확인할 수 있다. 별도 설치나 원본 수업 폴더 접근이 필요 없다. 이 검사는 실제 DB 적재·PDF 확인·의미 검증 완료를 뜻하지 않는다.

수업 코드 원문은 Markdown 코드 블록이어서 Run All로 실행되지 않는다. 각 발췌에 원래 노트북 파일명, 전체 셀 순번(1부터), 발췌 SHA-256을 기록했다. 노트북 metadata.reference_package.provenance에도 같은 출처를 넣었다. 출력·API 키·DB 인증정보·실습 초기화 명령은 옮기지 않았다.

참고 자료의 유일한 수업 범위는 `3_LLM_지식추출`이다. 원본에서 가져온 사업보고서 처리와 학교 도메인에 맞춰 새로 작성한 코드의 표시는 구분되어 있다. 수업 원본이 참조하는 회사 목록/정답/DB 등의 외부 데이터는 제공하지 않으며, 원본 실행이 목적이 아니다. 독립 예시가 같은 원리를 입력 인수와 인공 데이터로 보여 준다.

실제 구현에서는 ref_ 예시를 서비스 모듈로 그대로 import하지 않는다. 로컬 실행 이력과 실제 승인 청크·사전을 준비하고, 새 함수로 명시적인 입력·출력·실패 처리를 작성한다. 공통 파일이 이미 있으면 이를 import하고, 개인 폴더에 별도의 확정 계약을 만들지 않는다.
