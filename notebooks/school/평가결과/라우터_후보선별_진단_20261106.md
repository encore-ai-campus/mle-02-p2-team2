## 4. 원인 정리 (사실에 근거한 판단)

1. **경로 셋 중 전수 훑기가 나머지를 포함한다.** 역할 경로와 청크 검색 경로는 후보를 더하지 못하고 가산점(via, 청크 순위)만 준다. 사실상 "행동 444개 전부를 손으로 만든 점수식으로 줄 세우기"다.
2. **검색 단위가 행동이라 행동이 없는 근거는 구조적으로 놓친다.** 정의·기준·행정 절차 질문 9문항이 이에 해당한다. 원문 인용 경로가 일부를 보완하지만 2문항만 살렸다.
3. **점수가 내용보다 메타데이터(역할 +4·단계 +3·질병 +3)에 좌우된다.** 내용 일치는 글자쌍으로만 재서 표현이 다르면 0점이다.
4. **문턱이 걸러내지 못하고, 고정 상한(8개)과 (역할, 문서) 분산이 출력 수를 정한다.** 그래서 필요 여부와 관계없이 늘 8개 안팎이 나온다.
5. **라우터는 골든 표현에 맞춘 단어 목록이다.** 다른 표현에서는 의도 판단과 범위 밖 판단이 모두 흔들린다. 교직원 질문은 "학교가 할 일"과 "그 병의 기준"이 섞여 있는 경우가 많은데, 규칙은 이것을 ACTION 하나로 보낸다(15/15).
6. **'답변 완료'의 기준이 "Finding이 있음"이다.** 질문의 각 부분에 답했는지는 보지 않는다. 그래서 A06처럼 답이 없어도 ANSWERED가 되고, 재검색 루프도 돌지 않는다.
7. **다듬기 검사기는 '근거에 없는 조언'을 잡지 못한다.** 숫자·주체·강한 표현이 없는 지어낸 문장(P04)은 통과한다. 반대로 검사에 걸리면 긴 템플릿 목록으로 되돌아가, 화면 품질이 가장 나쁜 경우가 된다.

## 5. 수정 방향 (제안 — 미구현)

### A. 라우터를 LLM 구조화 분류로

- LLM 1회 호출로 아래 값을 받는다. 출력 형식을 고정하고 enum으로 검사한다.
  - `response_type`(DOMAIN/GENERAL/OUT_OF_SCOPE)
  - 주 의도와 보조 의도(복수)
  - 의도별 **하위 질문**
  - 질병·역할·단계 표현과 confidence
- 질병·역할 이름은 사전으로 정규화·검증만 한다. 사전에 없으면 버린다. 결정은 LLM, 정규화는 사전이 맡는다.
- 실패·시간 초과·형식 위반이면 지금의 규칙 분류기로 되돌린다. 실행 기록에 두 결과를 함께 남긴다.
- 하위 질문은 각 Tool의 `ToolInput.question`으로 쓴다. 복합 질문 처리와 검색어 품질이 함께 좋아진다. 공통 계약은 바꾸지 않는다.
- 비용: `gpt-6-luna`(reasoning none) 1회에 약 1초 예상(미측정).

### B. 선별을 "넓게 찾기 → 필요한 것만 고르기" 2단계로

- **1단계 재현율.** 검색 단위를 행동이 아니라 **청크**로 바꾼다.
  - 하위 질문으로 hybrid 검색해 상위 약 30개 청크를 찾는다.
  - 그 청크에 붙은 행동과, 질문한 역할의 행동(역할을 물은 경우만)을 붙여 후보 카드를 만든다.
  - 전수 훑기는 없애거나 검색 결과가 빌 때만 쓴다.
  - 행동이 없는 청크도 1급 후보가 되므로 원인 2가 해소된다.
- **2단계 정밀도.** 고정 점수·문턱 대신 **재순위기**가 "이 질문에 답하는 데 필요한가"를 판정한다.
  - 권장: **LLM 판정(listwise).** 후보 20~30개(ID + 짧은 발췌 + 역할·단계·문서)를 주고, 필요한 ID만 고르게 한다. 고른 근거마다 "직접 답 / 조건·예외 / 불필요" 표시를 받는다.
    - ID 중에서만 고르므로 근거를 지어낼 수 없다.
    - 개수는 고정 8개가 아니라 판정 결과대로 정하고, 상한은 약 6개로 둔다.
  - 대안 1: 교차 인코더 재순위기(다국어 bge-reranker 등). 로컬 모델이라 Streamlit Cloud 메모리·의존성 부담이 크다. 외부 rerank API는 새 공급자와 키가 필요해 팀 결정 사항이다.
  - 대안 2: 현재 점수식의 가중치·문턱 튜닝. 근거는 다음과 같다.
    - 문턱은 지금도 거의 걸러내지 않는다. 문제는 숫자가 아니라 내용 판단을 글자쌍으로 한다는 점이다.
    - 개발용 26문항으로 가중치를 맞추면 과적합될 위험이 크다.
    - 그래서 튜닝만으로는 원인 2·3이 남는다. 비교 기준선으로만 남기는 것을 권한다.
- **유지할 결정적 안전장치:**
  - `allowed_document_ids`와 선정 쪽수 범위
  - 질병·조치 불일치 제외
  - 원문 단계 표시
  - SUPPORTED_BY 재확인과 DB 대조
  - 역할 예시 표기
- 재순위기는 "필요성"만 판단하고, 근거의 진위는 기존 검사가 맡는다.
- **내용 중복:** 같은 개념(ActionConcept)의 문서별 행동은 Finding을 문서별로 유지하되(계약), 재순위기 입력에서 한 묶음으로 보여 준다.

### B-2. 하위 질문별 충분성 판정과 답변 검사 보강

- **충분성 판정.** 재순위 단계에서 하위 질문마다 "답할 근거가 있음 / 없음"을 함께 받는다.
  - 하위 질문 중 하나라도 근거가 없으면 PARTIAL로 두고, 그 하위 질문을 맡을 Tool로 재검색 루프를 돌린다.
  - 예: P01은 "수두 등교 기준"을 disease_search로 보낸다.
  - 지금의 "Finding 있음 = ANSWERED"를 대신한다.
- **답변 검사 보강.**
  - (1) 각 줄이 인용 근거로 뒷받침되는지 LLM 판정(함의 검사)을 추가한다. 실패하면 그 문제를 알려 주고 1회 다시 쓰게 한다.
  - (2) 그래도 실패하면 긴 템플릿 대신 재순위로 고른 소수 근거만 짧게 보여 준다.
  - (3) 학부모 응대 문구처럼 근거 밖 조언이 필요한 질문은 "원문 근거 / 응대 예시(작성 문구)"를 화면에서 구분할지 팀과 정한다.

  - 라우트 정확도
  - 단계별 지연(분류, 재순위, 다듬기)
- 라우터용으로 일상 표현 질문셋(위 20개를 팀이 검수·보완)을 별도로 둔다.
- **교직원 실사용 질문셋.** 위 15개에서 시작해 30~40개로 늘리고, 세 사람이 각 영역 질문을 보탠다.
  - 정답 청크 대신 채점표를 둔다: 질문에 직접 답했나, 꼭 필요한 근거가 들어 있나, 불필요한 근거 수, 근거 밖 주장 유무, 지금 할 일과 이후 할 일 구분.
  - 사람이 채점하고, LLM 채점은 보조로만 쓴다.
  - 가능하면 실제 교직원(보건교사) 1명에게 10개만이라도 보여 주고 판정을 받는다.
- 함정 질문 S-T01~T03은 반드시 따로 본다. 재순위기가 "질문 전제에 맞는 근거"만 골라 함정 정정 근거를 버릴 위험이 있다.
