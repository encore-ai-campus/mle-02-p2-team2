# 청킹 troubleshooting

기록일: 2026-11-06 KST. Codex 구현·실행 기록. 원문 대조 출발점은 [5일차 진행상황의 추출 주석지 오류 상세 분석](https://www.notion.so/40f23bb22437803ab441e4568ff725bc). ABOUT 매핑의 생성 규칙은 변경하지 않았다. 공유 DB 쓰기·삭제, LLM 재추출, 자동 정답 수정, 커밋·push는 수행하지 않았다.

## 1. 역학조사 표에 복구 단계가 붙음 — 주석지 1·2·4·5·14·15번

**문제상황:** 표는 ‘라. 역학조사 시 협조사항’에 속하지만 주소에 ‘바. 복구 단계’가 붙었다. 잘못된 stage 선별과 답변을 유발할 수 있었다.

**원인:** 기존 `body_chunks()`는 페이지를 끝까지 읽고 마지막 경로를 `page_sections[page]`에 저장했다. `build_all_chunks()`가 그 경로를 같은 페이지의 모든 표에 붙였다. 표의 원문 위치는 고려하지 않았다.

**해결 순서:**

1. `structure.py`의 `document_structure()`로 전체 본문의 각 줄에 위치와 경로 스냅샷을 생성한다.
2. 표 번호로 해당 페이지의 원문 캡션 위치를 찾는다. 그 위치의 경로를 사용하고 페이지 마지막 제목은 사용하지 않는다.
3. 역학조사 체크리스트 앞의 번호 붙은 시행 조건을 표의 상위 제목으로 오인하지 않도록 체크리스트의 경로는 해당 소절까지 보존한다.
4. 171·179·182·185쪽 실제 자료의 모든 해당 표 행에 올바른 질병·‘라. 역학조사 시 협조사항’이 있고 ‘복구’가 없는지 검사했다.

## 2. 결핵·성홍열·수두 제목이 사라지고 백일해가 남음 — 3·14·15번

**문제상황:** 185쪽 수두와 182쪽 성홍열 표에 백일해 주소가 붙었고, 171쪽 결핵 표에서는 질병 절이 누락됐다.

**원인:** 제목 경로를 만들기 전에 표 중복 제거를 수행했다. 본문 줄의 4글자 조각이 표 텍스트에 60% 이상 있으면 제거하는 규칙이 질병 제목에도 적용됐다. 결핵 75%, 성홍열 약 69%, 수두 70%로 제거됐지만 백일해는 50%여서 남았다.

**해결 순서:**

1. 전체 원문에서 구조를 먼저 읽고 내용 중복 제거는 이후에 한다.
2. `clean_body_lines()`에서 제목과 명시적 표 캡션을 중복 제거 대상에서 제외한다.
3. 질병을 문자열로 추정해 경로를 고치는 대신 원문의 `1. 결핵`, `5. 성홍열`, `6. 수두` 제목을 그대로 보존한다.
4. 3번은 `6. 수두 > 라. 역학조사 시 협조사항`, 14번은 `1. 결핵 > 라. …`, 15번은 `5. 성홍열 > 라. …`로 생성됨을 회귀 검사했다.

## 3. 장·중제목·1) 항목 등 주소 계층 누락 — 6·16·19번 포함

**문제상황:** 제5장·Ⅰ 휴업 및 휴교·4 학생 빈발 감염병 등 상위 제목이 빠지고, 관찰실 표의 `3) 일시적 관찰 필요성 판단 및 실시`도 누락됐다.

**원인:** 로마 숫자와 숫자 제목을 같은 변수 하나에 넣어 덮어썼고, 한글 제목을 포함해 사실상 두 계층만 저장했다. `1)`은 분할 표식으로만 쓰였다. 선정 페이지만 순회해 앞의 비선정 페이지에 있는 제목을 활용하지 못했다.

**해결 순서:**

1. 장 / 로마 숫자 / 공백형 번호 / 점형 번호 / 한글 항목 / 괄호형 번호를 별도 계층으로 보존한다.
2. 비선정 페이지도 구조 파악에 사용하되, 최종 청크 출력은 manifest 선정쪽수로 제한한다. 사용자 manifest는 수정하지 않았다.
3. 반복 장 머리글은 현재 계층을 초기화하지 않으며, 새 장과 Markdown 부록 표제는 경계를 초기화한다.
4. ECP에서 `다. → 1) → 가.~바.`처럼 재사용되는 한글 목록과 바깥 `라. 회복 등 조치` 복귀를 처리한다. 연도·국가별 건수 등 숫자 데이터 줄을 제목으로 오인하는 일부 패턴도 제외한다.
5. 실제 238쪽의 `제5장 > Ⅰ 휴업 및 휴교`, 56쪽 관찰실 표의 `3)` 주소를 검사했다.

## 4. 여러 절을 한 청크에 넣고 마지막 절로 표시 — 7·17번

**문제상황:** 7번 본문은 가·나를 함께 다루지만 주소는 나만 표시했다. 17번은 행정직원·정보담당교사 업무와 바깥 회복 조치를 합친 뒤 회복 조치 주소를 표시했다.

**원인:** 기존 누적 분량이 200자 미만이면 제목을 만나도 계속 합쳤다. 합쳐진 청크의 경로는 마지막 제목으로 결정했다. 60자 미만 조각 병합 및 일부 삭제도 구조 경계를 고려하지 않았다.

**해결 순서:**

1. 제목·계층이 바뀌면 길이에 관계없이 분리한다. 서로 다른 소절을 최소 길이를 맞추려고 병합하지 않는다.
2. 짧은 유효 문단을 길이만으로 버리는 후처리를 제거했다. 기존 공백·쪽번호·짧은 추출 잡음 정리는 유지한다.
3. 동일 구조 안에서 최대 800자로 묶는다. 한 줄이 800자를 넘는 경우에도 문자를 버리지 않고 잘라 보존한다.
4. 실제 244쪽 가·나 분리와 310쪽 담당자별 분리, 바깥 회복 조치 분리를 확인했다. 19·50·199·801·1700자 합성 입력의 문자 보존도 검사했다.

## 5. 작업용 표 제목이 공식 제목으로 노출되고 본문의 표 참조가 사라짐 — 3·15·20번

**문제상황:** ‘표 3-10 수두 역학조사 협조 체크리스트’ 등 작업본 제목과 ‘원본 이미지 대조’ 메모가 공식 제목처럼 나왔다. 본문에는 ‘다음과 같음’만 남고 표 3-12·13·14 참조는 사라졌다.

**원인:** 청크 제목은 표 작업본의 제목을 그대로 사용했다. 표와 중복된 본문 줄을 제거하면서 캡션까지 제거했다. 185쪽에서는 변환본의 표가 소제목보다 먼저 있어 단순 앞 제목 상속으로도 정확한 소속을 알 수 없었다.

**해결 순서:**

1. 본문에서 같은 표 번호의 캡션을 찾으면 그 원문 제목을 청크 text·section에 사용한다.
2. 작업본 제목은 `working_table_title` 추적 필드로 분리한다. source_parts·원문 오프셋은 조작하지 않는다.
3. 본문 표 캡션은 참조로도 보존해 ‘다음과 같음’과 참조 대상을 함께 읽을 수 있게 한다. 다른 항목으로 넘어가면 청크를 나눈다.
4. `data/specs/school_layout_corrections.json`에 185쪽 표 3-10의 사용자 원본 대조 근거와 소절 보정을 명시했다. 보정 대상 소제목이 실제 본문에 없으면 오류로 중단한다.
5. 캡션 위치가 중복되면 임의 선택하지 않고 오류로 중단한다. 캡션을 특정하지 못하면 페이지의 공통 상위 범위만 남기고 `context_verified=False`로 표시한다.

**중요한 잔여 범위:** 최종 766개 표 행 중 원문 캡션으로 위치를 잡은 행은 205개, 검증된 185쪽 보정은 17개다. 나머지 544개 행은 공통 범위 fallback이며 정확한 표 위치·전체 주소가 검증된 것으로 보지 않는다. 개요표·이어지는 표·후보 제목 등이 포함된다. 이 수치는 표 개수가 아니라 행 개수다. 변환본만으로 확정할 수 없는 배치를 검증 완료로 표시하지 않았다.

## 6. 후속 코드와 기존 참조의 회귀 대응

- `chunk_audit.py`: 같은 ID가 존재하는지뿐 아니라 내용이 같은지 검사한다. 골든 인용은 문서·PDF 쪽·실제 발췌로 새 청크를 재탐색한다. 자동 정답 변경은 하지 않는다.
- `extraction_sample.py`: 오래된 청크 파일을 고정해서 읽지 않고 `--bundle`을 필수로 받는다. `--out-md`, `--out-json`으로 별도 검토본을 만들 수 있다. 기존 주석지 덮어쓰기 방지는 유지했다.
- `school_chunks_full.ipynb`: 오래된 ‘42건’ 고정 단정을 제거하고 현재 JSON의 인용 73건을 읽는다. 이전 승인 행동 438개가 있는 명시적 폴더를 사용한다. 표 행 ID 장부는 검사만 하고 저장하지 않는다. 새 산출물은 `candidate_bundle.json`으로 저장하고 이전 정답·DB와 혼용하지 않도록 설명했다. 과거 저장 출력은 지우고 코드 셀을 실제 재실행했다.
- ABOUT 생성 로직은 그대로이며 이번 적재 후보 호환성 검사에는 ABOUT을 넣지 않았다. 다른 담당자 구현, 계약·DB 스키마는 수정하지 않았다.

초기 전체 테스트의 임시 폴더 접근 및 DB 소켓 접근은 sandbox 권한 오류로 실패했다. 각각 승인된 실행으로 재시도해 위 결과를 얻었다. 전역 `git diff --check`에는 사용자가 작성 중인 기존 v1 주석지의 공백 경고가 있어 해당 주석을 임의 수정하지 않았다. 이번 청킹 변경 경로만 대상으로 한 `git diff --check -- <변경 경로들>`은 통과했다.

**평가 해석:** 실DB 읽기 검사는 기존 DB에서 후속 호출이 동작하는지 확인한 것이며 새 청크를 적재한 서비스 평가가 아니다. 신규 Hit@k·MRR·추출 precision/recall은 계산하지 않았다. 새 청크 수 증가를 검색 품질 향상으로 주장하지 않는다. 벡터 API·LLM 재추출은 미실행이고 해당 기능의 일반 회귀는 테스트 fixture 범위다.

## 8. 재현 명령과 산출물

프로젝트 루트에서 실행한다.

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest tests -q -p no:cacheprovider
.venv/Scripts/python.exe -X utf8 notebooks/school/평가결과/chunking_regression.py
.venv/Scripts/python.exe -X utf8 notebooks/school/평가결과/chunking_live_regression.py <저장할_live.json>
.venv/Scripts/python.exe -X utf8 notebooks/school/평가결과/extraction_sample.py --bundle <official_chunks.jsonl> --out-md <새_주석지.md> --out-json <새_표본.json>
```

- 최종 재생성·코드/manifest 해시·이행 목록: `data/interim/school/chunking_v2_20261105T223223_186130Z/`의 `summary.json`, `official_chunks.jsonl`, `extraction_inputs.jsonl`, `candidate_bundle.json`, `migration.json`, `citations.json`, `test_sheet.md`, `test_sample.json`.
- 실DB 증빙: `data/interim/school/chunking_v2_20261105T164237_963628Z/live.json`.
- 위 원시 산출물은 Git 제외 로컬 자료다. 노션에는 상세 로그·숫자만 기록하며 원시 파일을 업로드하지 않았다.
- 새 청크를 서비스에 적용하려면 fallback 표 소속 확인, 기존 행동의 문맥 영향 검토, 본문 ID·골든 참조 이행, 학교 범위의 승인된 DB 재적재·임베딩 갱신, 그 데이터로 검색/응답 품질 재평가가 필요하다. 이전 산출물·주석지는 비교 근거로 보존한다.
- 구현과 로그는 로컬 미커밋 상태다.
