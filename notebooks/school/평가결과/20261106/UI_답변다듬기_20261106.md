### 답변 다듬기의 안전장치 (검사기 `check_answer`)

다시 쓰는 것은 `answer` 문자열뿐이다. findings·citations·status·tools_used는 그대로다.

1. **인용 번호**: 내용 줄마다 `[n]` 1개 이상, 범위 안. 번호 없는 줄은 소제목(`**…**`, `…:`)과 `※ 확인하지 못한 부분`만 허용.
2. **숫자**: 그 줄이 인용한 근거 글에 같은 숫자가 있어야 한다(기간·인원·단계 날조 방지).
3. **주체**: 역할 사전 이름·별칭(대표 이름으로 묶음), 학교 밖 기관(보건소·교육청 등), 미등록 역할 표기(영양(교)사 등)는 인용한 근거에 있어야 한다. **역할 소제목 아래 줄은 그 역할이 근거에 있어야 한다**(구조로 생기는 오귀속 방지).
4. **강도**: '반드시·의무·법적·법령상·하여야·필수·신고'는 인용 근거에 같은 말이 있을 때만(예시를 의무로, 신고 주체를 바꾸는 것 방지).
5. 역할 예시 안내 문구(`※ 담당은 원문이 제시한 예시…`)는 코드가 붙인다.

### 사람 판독(작성자 Claude, 표본 12문항: S-Q01·Q04·Q06·Q10·O04·R01·E02·A03·F02·F03·T02·D01)

- 사실: 질문에 대한 직접 답이 첫 줄에 온다(예: S-D01 "홍역의 잠복기는 7~18일이며, 평균 10~12일입니다.[2]" — 템플릿은 표 행 3줄 나열).
- 사실: 함정 S-T02는 "열 한 번으로 바로 등록해야 한다고 단정할 수 없다"로 전제를 바로잡고 지금 할 일을 안내했다. S-T01·T03도 '반드시'·'보건교사 직접 돌봄' 전제를 근거로 정정했다.
- 사실: 검색이 정답을 놓친 문항(S-Q06·S-F02)은 엉뚱한 근거를 나열하지 않고 "근거에서 확인되지 않음"으로 답한다. 템플릿보다 검색 실패가 더 잘 드러난다.
- 발견·수정: v2의 S-R01은 학교장·교감 담당 행동을 **영양(교)사** 소제목 아래 두었다(줄 안에는 '학교장·교감 예시'라고 적었지만 구조상 오해 소지). → v3에서 소제목 검사와 프롬프트 규칙을 더했고, v3·v4에서는 '담당이 적혀 있지 않은 일'로 분리됐다.
- 한계: 검사기는 번호·숫자·주체·강도만 본다. **조건 누락**(예: 시나리오 예시라는 단서, 지역 차이)과 **요약 중 의미 변화**는 자동으로 잡지 못한다. 34문항 전수 판독은 하지 않았다.

## 3. Streamlit Community Cloud 배포 방법 (미실행 — 사용자 계정에서)

1. share.streamlit.io → GitHub 계정 연결(조직 저장소 `encore-ai-campus/mle-02-p2-team2` 접근 권한 필요).
2. New app → Branch `main`, **Main file path `src/rag/ui/app.py`**, Advanced settings → **Python 3.12**.
3. Secrets에 `secrets.toml.example`의 키(NEO4J_URI·USERNAME·PASSWORD·DATABASE, OPENAI_API_KEY, 선택 APP_PASSWORD)를 팀 `.env` 값으로 입력. 값은 저장소에 커밋하지 않는다.
4. 앱 공개 범위는 'private(초대한 사람만)' 또는 `APP_PASSWORD` 설정을 권장(OpenAI 비용·공유 DB 부하 보호).

- 사실: 공유 DB는 Aura(`neo4j+s://`)라 클라우드에서 접속 가능하다. 팀원 Tool은 실행 중 Git 제외 파일을 읽지 않는다(legal의 `blocks.jsonl`은 개발용 함수에서만 사용).
- 미확인: 클라우드 실제 배포·접속은 하지 않았다(저장소 push 전). 클라우드에서 `truststore`가 리눅스 인증서로 동작하는지는 배포 후 확인 필요.
