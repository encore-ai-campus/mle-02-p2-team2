# 검수 청크 v3 서비스 DB 이행 결과

사용자 요청에 따라 **2026-11-06 11:22 KST**에 학교 자료를 서비스 DB에 적용했다. 단일 트랜잭션 커밋 후 다시 읽어 후보와 대조했고, 전체 평가 후 **11:32 KST**에도 같은 상태임을 확인했다. 코드 커밋·push는 수행하지 않았다.

## 적용 범위와 결과

| 항목 | 적용 전 | 적용 후 / 검증 |
|---|---:|---|
| 대상 문서 | 학교 2개 | 교육부 매뉴얼·경기도 가이드북 두 문서만 |

관계 적용 전 합계는 HAS_CHUNK 1,139 + SUPPORTED_BY 470 + DONE_BY 340 + INSTANCE_OF 287 + ABOUT 162 + FOR_DISEASE 97 = 2,495다.

추가 노드는 792개, 후보에 없는 이전 노드는 41개(청크 9개·행동 32개)였다. 행동 32개와 청크 8개는 현재 manifest에서 제외된 경기도 PDF 54·56쪽의 이전 자료다. 나머지 청크는 재분할로 폐기된 교육부 p0049:b02다. 외부 영역에서 학교 노드로 들어오는 관계는 0개였고, 필수 사전 노드 누락도 0개였다.

기존 검수 문서·원문·manifest는 변경하지 않았다. 인용 이동은 `school.json`과 `school.md`의 청크 참조 14건만 이행했으며 질문·발췌·조건 등 의미 필드는 유지했다. 이전 골든 파일은 이행 폴더에 백업했다. 시나리오 6개에서 미확정인 캡션은 추측하지 않고 확인된 상위 주소까지만 적용했다.

현재 적용본은 `data/specs/school_active_dataset.json`에도 기록했다. `school_load.ipynb`의 과거 패키지 고정 경로를 제거하고 이 파일의 명시적 패키지를 읽도록 연결했다. 패키지 노드/관계 검증 및 노트북 문법 검사를 통과했으며, 로컬 파일이 없다고 이전 자료로 대체하지 않는다. 과거 저장 출력은 지웠고 스키마·사전 초기화·쓰기 셀을 다시 실행하지 않았다.

## 적용 방식과 보호 장치

1. 학교 노드의 모든 속성·기존 임베딩·관계를 `before.json`에 저장했다. 자격 증명은 저장/출력하지 않았다.
2. 현재 코드·원문으로 후보를 다시 생성해 적용 대상과 일치함을 검사했다.
3. 학교 문서 두 개 밖의 후보, 외부 incoming 관계, 예상하지 못한 관계 유형, 변경된 ABOUT 근거 행은 거부한다.
4. 기존 임베딩은 본문·모델·장부 해시가 같을 때만 재사용한다. 변경 임베딩은 **DB 교체 전에** 생성·차원·유한수 검사 후 저장했다. 모델은 기존과 같은 `text-embedding-3-small`이다.
5. 사전 점검 이후 학교 데이터가 바뀌지 않았는지 트랜잭션 안에서 다시 검사했다.
6. 이전 학교 관계 정리 → 폐기 노드 삭제 → 새 노드·관계·벡터 적용 → 전체 대조를 **한 트랜잭션**에서 수행했다. 삭제는 DETACH가 아니므로 새로운 외부 참조가 생기면 실패·롤백한다.
7. 다른 영역·사전 상태도 트랜잭션 전후 비교했다. 조건 실패 시 커밋하지 않는다.
8. 커밋 영수증 저장 후 인덱스 ONLINE 상태와 실제 DB를 재확인했다. 전체 평가 후 학교 스냅샷 서명과 외부 영역 해시를 다시 대조했다.

## 실제 실행한 검증

- 전체 회귀 테스트: **258 passed**. 마이그레이션 범위·ABOUT 보존·동시 변경 감지·벡터 누락·관계 중복·복구 비교 등 7개 검사 포함.
- 변경 Python 5개 파일 린트 통과. 골든 JSON/Markdown 변경 경로의 `git diff --check` 통과.
- 실DB fulltext 메인 대표 질문: **3/3 ANSWERED**, 인용 2·2·10개. 유행성각결막염 휴업, 유행성이하선염 휴업, 유증상 학생 발견 시 담임·보건교사 역할을 확인했다. 각 출력의 DB 근거 대조도 통과했다.
- `allowed_document_ids=[]`: 인용 0개·INSUFFICIENT_EVIDENCE.
- 메인 평가: Action·Disease·Legal·CrossDoc 네 Tool을 실제 registry로 등록해 **40문항** 실행. 이번 질문셋에서는 호출 0회 4문항·1회 36문항이며 2~3회 실DB 재진입은 발생하지 않았다. 그 경로는 단위 회귀 범위와 구분한다.

## 재현 및 복구

실행 폴더: `data/interim/school/service_migration_20261106T021438_207504Z/` (Git 제외 로컬 자료).

- `before.json`, `preflight.json`: 적용 전 전체 학교 데이터·벡터·관계 및 차이.
- `vectors.json`, `prepared_plan.json`, `effective_bundle.json`: 준비한 임베딩과 ABOUT을 보존한 적용 패키지.
- `receipt.json`, `after.json`, `final_verification.json`: 커밋 및 최종 대조 증빙.
- `golden_before.json`, `golden_before.md`, `golden_migration.json`, `golden_applied_hashes.json`: 골든 참조 복구 자료.
- `live_fulltext.json`: 대표 질문 출력.
- `eval/{metadata,search,tool,main,summary}.json`: 전체 평가 원시 결과. 원시 파일은 저장소/노션에 업로드하지 않았다.

```powershell
# 읽기 검증
.venv/Scripts/python.exe -X utf8 notebooks/school/평가결과/apply_reviewed_migration.py --candidate data/interim/school/chunking_v3_20261106T014406_232762Z --phase verify --migration-dir data/interim/school/service_migration_20261106T021438_207504Z

# 새로운 폴더로 평가 재실행 (DB 쓰기 없음)
.venv/Scripts/python.exe -X utf8 notebooks/school/평가결과/service_migration_eval.py --out <새_결과폴더>
```

복구 명령은 **실행하지 않았다.** 필요 시 같은 이행 도구의 `--phase rollback`을 사용한다. 이행 이후 학교 DB 서명이나 현재 골든 파일 해시가 달라졌으면 자동 복구를 거부한다. 복구는 이전 속성·임베딩·관계를 한 트랜잭션으로 되돌리고 다른 영역 불변을 검사한 뒤 이전 골든 참조를 복원한다. 내부 elementId가 재배정돼도 실제 속성·관계를 비교하도록 구성했으며, 비교 로직은 인공 스냅샷으로 검증했다. 실제 운영 복구 리허설을 수행했다고 주장하지 않는다.

**현재 상태:** 검수 청크 v3는 서비스 DB에 적용 완료. 데이터 정합성 검증 완료. 검색 품질·충분성에는 위 미해결 항목이 남아 있다. 저장소 변경은 로컬 미커밋이다.
