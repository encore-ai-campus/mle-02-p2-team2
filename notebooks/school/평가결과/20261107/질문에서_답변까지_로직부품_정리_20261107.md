# 질문에서 답변까지 — 사용하는 로직(부품) 총정리 (2026-11-07 기준)

- 목적: 질문 하나가 답변이 되기까지 거치는 **모든 부품**을 한곳에 정리한다. 발표 04 기술 파트와 팀원 설명용이다.
- 기준: 11/07 현재 `main` 작업 트리의 학교 영역 코드와 화면(Streamlit) 조립. 코드 이름이 아니라 **하는 일** 중심으로 쓴다.
- 범위: 학교 행동 Tool(주승우)은 내부까지 자세히 적는다. 질병·법령·문서 비교 Tool은 메인 그래프에서 보이는 역할만 적는다(내부는 담당자 확인).
- 이 문서는 설명서다. 성능 수치는 [발표용 총정리](발표용_전체과정_검색품질_총정리_20261107.md)와 [답변 품질 결과](답변품질_개선_결과_20261107.md)를 본다.

## 0. 한눈에 보기

```text
[미리 준비된 것] 원문 → 청크 → 행동 추출·사람 검수 → 지식그래프(Neo4j) + 단어 색인 + 벡터 색인

질문 ─▶ ① 입력 확인 ─▶ ② 질문 이해(LLM 라우터) ─┬─▶ ③ 판단 기준 원문 조회 (동시에 실행) ──────────┐
                                               └─▶ ④ Tool 선택·실행·재탐색(최대 3회)              │
                                                     └ 학교 행동 Tool: ⑤ 찾기 → ⑥ 거르기 → ⑦ 정렬 → ⑧ 결과·검증 │
                                               ⑨ 합치기·충분성 판단 ◀────────────────────────────┘
                                               ⑩ LLM 근거 선별(최대 10개, 판단 기준은 항상 유지)
                                               ⑪ 판단형 답변 작성(LLM) ─▶ ⑫ 줄 단위 검사 ─▶ ⑬ 화면(스트리밍·근거 문서)
```

| 묶음 | 부품 번호 | 한 줄 요약 |
|---|---|---|
| 질문 이해 | ①②③ | 무엇을 묻는지, 어떤 상황인지, 무엇을 꼭 확인해야 하는지 정한다 |
| 근거 찾기 | ④⑤ | 넓게 찾는다(단어+vector 검색, 그래프 조회, 판단 기준 원문) |
| 근거 거르기·정렬 | ⑥⑦⑧⑨⑩ | 틀린 근거를 빼고, 줄 세우고, LLM이 꼭 필요한 것만 고른다 |
| 답변 쓰기·검사 | ⑪⑫⑬ | 근거로 판단해 쓰고, 줄마다 근거와 대조한 뒤 보여 준다 |

**LLM이 하는 일은 세 곳뿐이다**: 질문 이해(②), 근거 선별(⑩), 답변 작성(⑪). 나머지는 모두 규칙·DB 조회·글자 대조다. 질문당 LLM 호출은 3회이고, 답변 첫 줄이 검사에 걸리면 1회가 더해진다. 모델은 세 곳 모두 gpt-6-luna다.

## 2. 질문 이해

### ① 입력 확인
- 질문·지역·**허용 문서 목록**을 확인한다. 이후 모든 조회는 허용 문서 안에서만 한다. 빈 목록이면 "쓸 수 있는 문서 없음"이다.
- 우선 문서 목록이 있으면 같은 점수일 때만 앞에 둔다(순위 힌트일 뿐 허용 범위를 바꾸지 않는다).
- 화면 기본값은 DB에 적재된 문서 10종 전체다. 골든 평가는 5종을 쓴다.

### ② 질문 이해 — LLM 라우터
LLM 한 번으로 아래 여섯 가지를 **정해진 형식(선택지)**으로만 받는다. 형식이 틀리거나, 시간이 초과되거나, 오류가 나면 규칙 분류기로 되돌아간다.

| 받는 것 | 내용 | 예 |
|---|---|---|
| 범위 | 감염병 대응 질문 / 인사·사용법 / 범위 밖(진단·처방·잡담 등) | "오늘 메뉴 추천" → 범위 밖 |
| 의도 | 학교 행동 / 질병 사실 / 법령 / 문서 비교. 중요한 순서로 최대 3개 | "백일해, 학교가 보건소에 알려야?" → [학교 행동, 법령] |
| 하위 질문 | 의도별로 따로 묻는 질문. 일상어를 문서 용어로 바꾼다 | '독감'→'인플루엔자', '며칠 쉬어야'→'등교중지 기간' |
| 문서 용어 검색 문장 | 병명·학생 같은 개별 사례를 뺀 **개념 수준 검색 문장** | "독감 걸린 애 며칠 쉬어요?" → "감염병별 등교중지 기간" |
| 상황 | 질문 속 사실만 옮긴다: 질병, 확진·의심·증상, 인원, 발생 범위, 질문자 역할 | "전교생 5명 코로나 확진, 교장인데" |
| 확인 항목 | 묻지 않았어도 답하려면 확인해야 할 판단 기준: 신고 대상인지, 법정감염병 급수, 대응 단계·유행의심 기준, 신고 의무자, 미신고 벌칙, 등교중지 기간 | 코로나 5명 → 신고 대상·급수·유행의심 기준 |

- **규칙 분류기(예비):** 승인 사전의 질병·역할 이름과 단서 낱말로 범위·의도를 정한다. LLM이 없거나 실패하면 이것을 쓴다.
- **확인 항목 보완 규칙:** LLM이 빠뜨린 항목을 질문 낱말로 더한다(지우지는 않는다). 예: "신고" → 신고 의무자, "출석" → 출석 인정, 역할을 밝힘 → 역할별 단계 할 일, 여러 명 → 대응 단계, 확진·의심 → 등교중지 기간.
- 라우터는 답하지 않는다. 범위 밖이면 그 사유만 사용자에게 보이는 한 문장으로 쓴다.
- 인사·사용법·범위 밖 질문은 Tool 없이 바로 안내문으로 끝난다.

### ③ 판단 기준 원문 조회
- 확인 항목마다 **정해 둔 원문 패턴**으로 DB에서 원문을 직접 찾는다. 예: 학교장 신고 대상 감염병 목록, 유행의심 기준, 대응 제3단계 상황, 감염병예방법의 신고의무자 조항, 미신고 벌칙, 질병별 등교중지 기간, 경기도 가이드북의 역할별·단계별 할 일 표.
- **Tool 실행과 동시에** 돈다(라우터 결과가 나오자마자 시작한다).
- 코드가 판정하는 것은 **글자 대조뿐**이다. 질병 이름이 신고 대상 목록 원문에 있는지, 질병 이름 가까이에 "제N급"이 적혀 있는지를 본다. 이 결과를 "코드가 원문과 대조한 사실"로 답변 작성기에 넘긴다.
- 여기서 찾은 근거는 **판단 기준**으로 표시하고, LLM 선별(⑩) 뒤에도 항상 남긴다.
- 왜 넣었나: 신고 대상 목록이나 벌칙은 사용자가 묻지 않은 항목이라 검색어가 되지 않았다. 그래서 답변이 조건("신고 대상이면…")을 판단하지 못하고 옮기기만 했다.

## 3. 근거 찾기

### ④ Tool 선택·실행·재탐색 (메인 그래프)

| Tool | 담당 | 하는 일 |
|---|---|---|
| 학교 행동 검색 | 주승우 | 학교가 할 일·담당 역할·대응 단계와 원문 근거 |
| 질병 정보 검색 | 송수림 | 잠복기·전파·증상·관리 기준 같은 질병 사실 |
| 법령·신고 검색 | 유종혁 | 학교 보고·학교장 신고·의료기관 신고 주체 구분. 사람이 원문을 읽고 만든 답 카드가 있는 질문에 답한다 |
| 문서 비교 그래프 | 송수림 | 같은 개념에 대한 교육부/경기도 문서별 행동·담당·단계 비교 |

- 주 의도의 Tool을 먼저 부른다. 근거가 충분하면(답변 완료) 추가 호출 없이 끝낸다.
- 부족할 때만, **명시적 신호**가 가리키는 아직 안 부른 Tool을 부른다. 신호는 라우터의 보조 의도와 Tool이 남긴 "확인 못함: ○○ Tool 필요" 경고, 두 가지뿐이다.
- 질문당 최대 3회, 같은 Tool은 한 번만 부른다. 두 번째부터는 앞선 Tool이 확인한 질병·개념을 다음 Tool에 넘긴다.
- 복합 질문이면 Tool마다 자기 하위 질문을 넘기고, 원 질문은 참고로 함께 넘긴다.
- 연결되지 않은 Tool을 골랐으면 호출하지 않고 "연결 오류"로 남긴다. 다른 Tool로 대신 답하지 않는다.
- 다른 담당자 Tool은 화면 조립 단계에서 연결한다. 메인 그래프 코드는 다른 담당자 폴더를 직접 가져다 쓰지 않는다(팀 규칙).

### ⑤ 학교 행동 Tool — 넓게 찾기

| 부품 | 하는 일 | 왜 |
|---|---|---|
| 질문 계획 | 승인 사전으로 질문 속 **역할·질병·단계·조치어**(휴업·등교중지·소독 등)를 읽는다. 질문 문장은 바꾸지 않는다 | "담임에게 알린다"처럼 '…에게'로만 나온 역할은 수행자로 보지 않는다 |
| 검색어 만들기 | 질문 낱말 + 질문에 나온 역할·질병의 공식 표기와 별칭 | '보건교사'로 물어도 '보건(담당)교사'를 찾게 |
| **hybrid 검색** | **단어 기반(fulltext)과 vector를 합친 검색**. 두 결과는 점수 범위가 달라서 더하지 않고, **순위로 합친다(RRF)** | 단어 검색은 정확한 용어에, vector는 비슷한 뜻에 강하다 |
| **두 질의 검색** | 원 질문과 라우터의 **문서 용어 검색 문장**으로 각각 hybrid 검색하고, 다시 순위로 합친다. 두 검색은 동시에 실행한다 | "성홍열도 학교장이 신고해야 하나요?"로는 60위였던 신고 대상 목록이 문서 용어 질문으로는 6~10위 |
| 넓은 후보 | 검색 후보 30개, 조치어가 있는 질문은 최대 64개 | 거르기 뒤에도 근거가 남게 |
| **그래프 확장** | 검색된 청크 ─ 그 청크에 근거를 둔 행동 ─ 담당 역할·행동 개념·질병을 관계로 따라간다 | 원문 문장을 "누가·무엇을" 단위로 바꿔 쓸 수 있다 |
| 역할 직접 조회 | 질문에 역할이 있으면 그래프에서 그 역할이 하는 행동을 직접 가져온다(최대 8개) | 검색어와 표현이 달라도 역할 행동을 놓치지 않게 |
| 행동 전체 훑기 | 허용 문서의 행동 전체를 점수로 훑어, 청크 검색이 놓친 행동을 더한다(최대 6개, 최소 점수 이상만) | 재현율 보조 |
| 원문 인용 | 행동이 붙지 않은 청크는 원문 그대로 인용 후보로 둔다(최대 12개) | 본문은 행동 추출을 하지 않아서 원문으로 보완한다 |

## 4. 근거 거르기와 정렬

### ⑥ 안전장치 (거르기)

| 안전장치 | 빼는 것 |
|---|---|
| 허용 문서 재적용 | 모든 조회 단계마다 허용 문서 밖의 결과 |
| 선정 쪽수 | 서비스 범위로 정하지 않은 쪽의 청크 |
| 다른 질병 제외 | 질문한 질병과 다른 질병의 표 행·절(표는 행의 질병명, 본문은 가장 가까운 질병 절로 판단) |
| 조치 불일치 제외 | 휴업·등교중지·소독 등을 물었는데 그 조치가 없는 근거 |
| 관계 재확인 | 행동 ─ 근거 청크 관계를 DB에서 다시 확인하지 못한 행동 |
| 본문 직접 근거 우선 | 특정 질병·조치의 본문 근거가 있으면 일반 지침·모의훈련 시나리오로 남은 자리를 채우지 않는다 |
| 단계 표시 | 질문 단계와 다른 단계에 배치된 원문은 빼지 않고 "원문 배치 단계가 질문 단계와 다름"을 붙인다 |

### ⑦ 정렬 (줄 세우기)

| 순서 | 부품 | 방식 |
|---|---|---|
| 1 | 순위 결합(RRF) | 단어·vector 검색, 두 질의의 순위를 합친다. 순위만 쓰고 점수는 더하지 않는다 |
| 2 | **규칙 점수표** | 행동마다 점수를 매겨 내림차순으로 정렬한다. 질문 핵심어와 겹친 글자 수, 질문한 역할이 수행자면 가산·다른 역할이면 감점, 단계·질병·행동 개념 일치 가산, 검색 순위가 높을수록 가산. **의미 판정이 아니라 후보를 거르는 용도** |
| 3 | 번갈아 뽑기(다양화) | (질문한 역할, 문서) 묶음을 돌아가며 뽑는다. 상한은 행동 16개 | "담임·보건교사 각각" 질문에서 한 역할·한 문서가 상위를 독차지하지 않게 |
| 4 | 단계 우선 | 질문 단계와 같은(또는 단계 미지정) 행동을 앞에 둔다 |
| 5 | 묶음 순서 | 메인에서 합칠 때 **판단 기준 원문 → Tool 결과** 순서. LLM 선별에는 이 순서대로 앞 36개가 들어간다 |

### ⑧ Tool 결과 만들기와 검증
- **결과 세 가지**
  - 주장(Finding): 원자적 주장 하나. 예: "보건교사는 ○○를 한다"
  - 출처(Citation): 실제 청크의 문서·PDF 쪽·인쇄 쪽·원문 발췌
  - 그래프 경로(GraphPath): 실제 조회한 관계를 저장 방향 그대로 담는다
- **형식 검사:** 팀 공통 계약에 맞는지 본다.
- **DB 대조:** 청크가 실제로 있는지, 그 문서의 청크인지, 쪽수가 맞는지, 발췌가 원문에 글자 그대로 있는지, 행동 ─ 청크 관계가 실제로 있는지 확인한다.
- 통과하지 못한 주장·경로는 **고치지 않고 빼며**, 사유를 경고로 남긴다.
- 학교 행동 Tool은 스스로 이 검증을 하고, 다른 Tool 결과는 메인 그래프가 합칠 때 같은 방식으로 DB에 대조한다.

### ⑨ 합치기와 충분성 판단
- 같은 청크는 출처 하나로 합치고, 주장은 근거별로 그대로 둔다.
- 상태는 네 가지다: **답변 완료 / 일부 확인 / 근거 부족 / 실행 오류**. 부족하면 ④로 돌아가 재탐색할지 정한다.

### ⑩ LLM 근거 선별 (재순위·선별)
- 근거를 **카드**로 보여 준다. 카드 하나는 청크 하나이고, 그 청크로 만든 주장과 원문 발췌가 들어간다. 카드는 최대 36개다.
- LLM은 **카드 번호 중에서만** 고른다(최대 10개). 없는 번호는 버린다. 근거를 새로 만들 수 없다.
- 고르는 기준은 세 가지다.
  - 직접 답하는 근거
  - 적용에 꼭 필요한 조건·예외·시점·담당
  - 질문의 전제가 원문과 다를 때 그것을 보여 주는 근거
- 문서가 다르면 문서마다 하나씩 고른다. 모의훈련 시나리오나 다른 단계 근거는 본문 지침이 없을 때만 고른다.
- 고른 근거마다 **핵심 구절을 원문 그대로** 받고, 코드가 원문에 실제로 있는지 글자 대조한다. 없으면 그 구절은 버린다.
- 같은 호출에서 하위 질문마다 **답함 / 일부 / 근거 없음**을 받아 상태와 "확인하지 못한 부분"에 반영한다.
- 판단 기준 근거(③)는 고르지 않아도 항상 남긴다.
- 실패하거나 시간이 초과되면 선별 없이 기존 근거를 그대로 쓴다.
- 왜 넣었나: 11/06 진단에서 문항당 인용이 9개 안팎이었고, 정답 비율이 약 10%였다. "넓게 찾는 일은 Tool, 고르는 일은 선별 단계"로 나눴다.

## 5. 답변 쓰기와 검사

### ⑪ 판단형 답변 작성 (LLM)
- **입력:** 고른 근거([n] 번호), 핵심 구절, 질문 상황, 코드가 대조한 사실, 근거 표시(시나리오 예시·원문 단계).
- **형식:** 굵은 결론 1~2문장 → 상황 판단 → 지금 바로 할 일(시간 순, 번호 목록) → 이후에 할 일 → 학교 내 다른 담당의 역할 → 신고·법적 사항 → "※ 확인하지 못한 부분". 필요한 소제목만 쓴다.
- **적용 판단 허용:** 근거의 규칙에 질문 상황을 대입해 결론을 쓴다. 예: 신고 대상 목록에 코로나19가 없으면 "목록에 없습니다". 단 규칙 근거 번호를 붙여야 한다.
- **금지 규칙:** 근거에 없는 사실·숫자·기관을 쓰지 않는다. 신고 주체를 바꾸지 않는다. 예시 담당을 의무처럼 쓰지 않는다. 보건소·의료기관이 하는 조치를 학교가 할 일로 쓰지 않는다. 판단할 사실이 빠졌으면 "같은 반이면 …, 아니면 …"으로 나눠 쓴다.

### ⑫ 줄 단위 검사 (코드)

| 검사 | 걸리는 경우 |
|---|---|
| 인용 번호 | 내용 줄에 [n]이 없거나 없는 번호를 썼다 |
| 숫자 | 그 줄이 인용한 근거에 없는 숫자(질문 속 숫자는 허용) |
| 주체 | 그 줄이 인용한 근거에 없는 역할·기관 이름(같은 대상의 다른 표기는 같게 본다. 예: 학교의 장 = 학교장) |
| 강한 표현 | 근거에 없는 '반드시·의무·법적·신고' 같은 표현 |

- **처리 규칙**
  - 걸린 줄은 빼고, 통과한 줄만 내보낸다.
  - 소제목의 담당이 근거에 없으면 줄은 남기고 "담당이 적혀 있지 않은 내용" 소제목 아래로 옮긴다.
  - "확인되지 않았다"처럼 근거가 없음을 밝히는 줄은 주장이 아니어서 주체·강도 검사를 하지 않는다.
- **맥락 표시(코드가 덧붙임)**
  - (시나리오 예시)
  - (원문: 대응 제N단계)
  - (원문 조건: 격리 해제 후 등)
  - 시나리오만 근거인 첫 줄에서는 "네/아니요" 결론어를 지운다.
- **다시 쓰기와 되돌리기**
  - 첫 줄(결론)이 걸리면 걸린 이유를 알려 **한 번만 다시 쓰게** 한다.
  - 그래도 걸리거나, 통과한 줄이 없거나, 걸린 줄이 통과한 줄보다 많으면 **템플릿 답변**으로 되돌린다. 템플릿 답변은 검증된 주장을 역할별로 묶은 근거 목록이다.
- **코드가 붙이는 줄**
  - 벌칙을 물었는데 답변에 벌칙이 없고 판단 기준 조회가 벌칙 원문을 찾았으면, 원문 문장을 그대로 덧붙인다.
  - "담당은 원문이 제시한 예시입니다" 안내도 LLM이 아니라 코드가 붙인다.
  - 내부 경고 문구는 사용자에게 보이지 않게 정리한다.

### ⑬ 화면
- **스트리밍:** 결론 줄이 검사를 통과한 뒤부터 줄 단위로 보여 준다. 다시 쓸 수 있게 그 전에는 내보내지 않는다.
- **근거 문서:** 문서명·판본·PDF 쪽으로 표시한다. 공식 URL이 확인된 문서만 링크를 붙인다. 원본 PDF는 넣지 않는다.
- **개발자 화면:** 처리 흐름(노드별 기록), 사용한 Tool, 그래프 경로를 보여 준다.
- **질문 이력:** 질문·상태·의도·Tool·처리 시간을 로컬 파일에 저장한다. 답변 본문과 키는 저장하지 않고, 설정으로 끌 수 있다.
- **API 키가 없을 때:** 규칙 분류, 선별 없음, 템플릿 답변으로 동작한다.

## 7. LLM과 코드의 역할 분담

| 단계 | LLM이 하는 일 | 코드가 하는 일 |
|---|---|---|
| 질문 이해 | 범위·의도·하위 질문·문서 용어 검색 문장·상황·확인 항목 | 선택지 형식 강제, 실패 시 규칙 분류, 확인 항목 보완, 질병·역할 이름은 사전으로만 인식 |
| 근거 찾기 | (없음) | hybrid 검색, 두 질의 결합, 그래프 확장·조회, 판단 기준 원문 패턴 조회, 글자 대조 판정 |
| 거르기·정렬 | 꼭 필요한 근거 고르기, 하위 질문별 충분성 | 안전장치, 점수표, 번갈아 뽑기, 카드 번호 확인, 핵심 구절 원문 대조, DB 대조 |
| 답변 | 판단형 문장 쓰기 | 줄 단위 검사, 맥락 표시, 1회 재작성 지시, 템플릿 되돌리기, 안내 줄 덧붙이기 |

한 줄로: **LLM은 해석하고 고르고 쓴다. 근거를 만들 수는 없고, 코드가 원문과 대조해 통과한 것만 남는다.**

## 8. 용어집

| 용어 | 뜻 |
|---|---|
| 청크 | 원문을 자른 검색 단위(표 행 1개 또는 본문 항목 묶음) |
| hybrid 검색 | 단어 기반(fulltext) 검색과 vector(뜻 유사도) 검색을 함께 쓰는 방식 |
| RRF | 여러 검색 결과를 점수가 아니라 **순위**로 합치는 방법. 여러 목록에서 위에 있을수록 앞에 온다 |
| 두 질의 검색(multi-query) | 원 질문과 개념 수준 문서 용어 문장으로 각각 검색해 합치는 것 |
| 그래프 확장 | 찾은 청크에서 관계를 따라 행동·역할·개념·질병으로 넓히는 것 |
| 판단 기준 | 신고 대상 목록·급수·유행의심 기준·신고의무자·벌칙·등교중지 기간처럼 상황을 판단하는 규칙 원문 |
| 확인 항목 | 답하려면 확인해야 할 판단 기준의 종류(라우터가 정하고 코드가 보완) |
| 상황 | 질문 속 사실(질병·확진 여부·인원·범위·질문자 역할) |
| 근거 선별 | LLM이 카드 중 꼭 필요한 근거만 고르는 단계(재순위) |
| 판단형 답변 | 근거 나열이 아니라 규칙에 상황을 대입해 결론·할 일을 정리한 답변 |
| 템플릿 답변 | LLM 문장 없이 검증된 주장만 역할별로 묶은 예비 답변 |
| 허용 문서 / 우선 문서 | 조회 범위(강제) / 같은 점수일 때만 쓰는 순위 힌트 |
| 근거 종류(직접 배정 / 예시) | 원문이 담당을 직접 정했는지, 예시로 제시했는지. 예시를 의무로 바꾸지 않는다 |
| 상태 4종 | 답변 완료, 일부 확인, 근거 부족, 실행 오류 |

## 9. 확인·수정할 점

1. **다른 담당자 Tool 내부(질병·법령·문서 비교)**는 메인에서 보이는 역할만 적었다. 발표에 내부 방식을 넣으려면 송수림·유종혁 님 확인이 필요하다.
2. 청크 "약 200자 단위"와 표 행 수는 청킹 v4.1 기록을 따랐다. 슬라이드에 숫자를 쓰기 전에 [발표용 총정리](발표용_전체과정_검색품질_총정리_20261107.md)의 값과 맞춰 보세요.
3. 행동 추출에 쓴 LLM 모델명은 이 문서에 적지 않았다(적재 기록 확인 필요).
4. 문서 용어 검색 문장의 효과 예(60위 → 6~10위)는 11/07 진단 사례 하나다. 전체 효과는 새로 준비한 검색 순위 측정(B 단계)으로 확인한다.
