# 답변 품질 개선 결과 — 근거 나열에서 근거로 판단해 주는 답변으로 (2026-11-07)

계기: Streamlit에서 실사용 질문 두 개를 넣었더니 답변이 매우 나빴다(사용자 지적).
- "전교생 5명 코로나 확진, 교장이 할 일"
- "담임인데 홍역이 반에 몇 명씩, 신고해야? 안 하면?"

원인 분석과 계획은 [답변품질_개선_제안서_20261107.md](답변품질_개선_제안서_20261107.md)에 있다. 사용자는 허용 문서 확대·적재를 팀에서 승인받았다고 했고, P0·P1을 모두 진행하라고 지시했다. 원칙은 "출력 형식이 아니라 내부 로직을 고쳐 모든 질문에 잘 답한다"였다.

상태: 구현 완료. 로컬 미커밋. 실DB는 읽기만 했다.

## 1. 바꾼 내부 로직

| 단계 | 바꾼 것 | 파일 |
|---|---|---|
| 상황 해석(P0-1) | 라우터가 같은 LLM 호출에서 `situation`(질병·확진/의심·인원·범위·질문자 역할·묻는 것)과 `checks`(확인할 항목)를 함께 낸다. 질문 낱말로 분명한 항목은 코드가 보탠다(`augment_checks`). | `router.py`, `checks.py`, `main_graph.classify_scope` |
| 확인 항목 조회(P0-2) | 새 노드 `check_facts`가 판단 기준 원문을 DB에서 직접 찾는다(읽기 전용, 허용 문서 안). 라우터 직후 백그라운드로 시작해 Tool 실행과 동시에 돈다. 아래 표 참조. | `checks.py`(새 파일), `main_graph.check_facts` |
| 코드 대조 사실 | 코드는 글자 대조만 한다: 질병명이 신고 대상 목록 원문에 있는지, 병명 가까이의 '제N급', 목록의 법적 근거(제12조·시행규칙 제8조), 제12조① 신고의무자 표기, 벌칙 문장 원문 추출. 결과를 `facts`로 근거 선별·작성기에 넘긴다. | `checks.gather_checks` |
| 근거 선별(P1-6) | 확인 근거는 선별 뒤에도 항상 남긴다(`pinned`). 선별 프롬프트에 질문 상황·대조 사실·[판단 기준] 표시를 넣는다. 상한 8 → 10. 판단 기준을 더한 뒤 모든 하위 질문이 '답함'이면 ANSWERED로 판정한다. | `rerank.py`, `main_graph.select_evidence` |
| 답변 작성(P0-4) | 결론 → 상황 판단 → 지금 바로 할 일 → 이후에 할 일 → 학교 내 다른 담당 → 신고·법적 사항 형식이다. 근거 규칙에 질문 사실을 대입한 적용 판단을 허용하되 규칙 근거 번호를 반드시 붙인다. 신고 주체를 바꾸지 않고, 문서 성격(의료기관용 신고 기준)을 표시한다. 역할 표 근거는 '지금 바로 할 일'에 쓴다. | `answer_writer.py` |
| 검사 보완 | 대조 사실을 그 근거 청크의 글로 인정한다. 목록 번호·병명 속 숫자(코로나19)는 숫자 검사에서 뺀다. 학교장 = 제12조의 '관리인, 경영자 또는 대표자'로 본다. 번호 없는 '확인되지 않습니다' 줄은 안내 줄로 본다. 번호 목록은 1부터 다시 매긴다. | `answer_writer.LineChecker` |
| 실패 처리(P0-5) | 첫 줄(결론)이 검사에 걸리면 걸린 이유를 알려 1회만 다시 쓴다. 통과 전에는 화면에 내보내지 않는다. 처벌을 물었는데 벌칙이 빠지면 벌칙 원문 인용 줄을 코드가 덧붙인다. 템플릿 답변과 사용자 화면의 '확인이 필요한 부분'에는 확인하지 못한 부분만 쉬운 말로 보이고, Tool 내부 경고는 개발자 화면에만 둔다. | `answer_writer`, `main_graph.compose_text`, `ui/sources.user_warnings` |
| 허용 문서(P0-3) | 화면 기본 허용 목록을 DB 전체 문서(10종)로 넓혔다(코로나19·호흡기·인플루엔자 등 질병관리청 지침 포함). 골든 평가는 기존 5종(`EVALUATED_DOCUMENTS`)을 그대로 쓴다. | `ui/service.py`, `ui/app.py` |

## 3. 해석과 한계

- **사실:** 같은 질문셋에서 루브릭 52 → 73(Claude 1인 채점), 템플릿 대체 2 → 0, 오답 1(D07) → 0. 골든 정답 인용은 유지됐다(27 → 28, 실행 변동 범위 안).
- **가설:** 개선의 핵심은 확인 항목 조회다. 사용자가 묻지 않은 판단 기준 원문(신고 목록·급수·유행의심 기준·조문·벌칙·역할 표)을 질문마다 가져온다. 형식 변경만으로는 D01·D02·D07·D13을 고칠 수 없었다(v1에서 형식만 바꿨을 때 D07 "확인 안 됨", D02 벌칙 누락).
- **응답 시간:** 중앙값 약 2초 늘었다. 원인은 답변이 길어지고 근거 카드가 늘어난 것이다. 확인 항목 조회는 병렬·동시 실행으로 0.2~0.5초 대기까지 줄였다. 처벌·법령이 함께 나오는 질문(D02·D07·D13)은 법령 Tool 호출이 더해져 16~22초다.
- **남은 약점:**
  - D05 식중독은 감염병 대응 일반 조치만 나오고, 보존식 등 식중독 특화 조치는 근거를 찾지 못했다(교육부 43쪽 시나리오에 있음).
  - 보건교사 부재 시 대체자처럼 자료에 없는 내용은 "정해져 있지 않음"으로 답한다.
  - 루브릭은 1인 채점이고 질문셋은 Claude가 만들었다. 실행마다 LLM 문장이 달라진다.
- **법령:** 벌칙은 질병관리청 호흡기 지침의 요약 문장을 쓴다. 법령 원문 조항(제79~83조)은 적재되지 않았다.
