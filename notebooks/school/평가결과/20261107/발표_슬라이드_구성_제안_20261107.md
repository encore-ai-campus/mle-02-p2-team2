### 손볼 점 (제안만, 수정하지 않았다)

1. **목차와 구분 쪽이 다르다.** 목차(2쪽)는 `01 배경 / 02 서비스 개요 / 03 기술 / 04 스키마 구조도 / 05 시연 / 06 검증 & 회고`다. 구분 쪽은 `01 배경 / 02 서비스 개요 / 03 구조 설명 / 04 기술 / 05 시연 / 06 발전 경과 / 07 한계 및 기대효과`다. 말씀하신 순서(배경 → 개요 → 구조 → 기술 → 시연 → 발전 경과 → 한계·기대효과) 7개로 목차를 맞추면 된다.

3. **12쪽 구조도 그림.** 지금 구현과 대조해 확인이 필요하다. 구현은 `라우터(LLM) → Tool 4개(학교 행동·질병·법령·문서 비교) → 근거 평가·재탐색 → LLM 근거 선별 → 답변 작성(줄 단위 검사)`이다. 그림에 근거 선별 단계가 없거나 Tool 이름이 다르면 11/07 기준으로 맞추는 것이 좋다.
4. **역할분담 템플릿(27쪽)은 4명 카드다.** 팀이 3명이므로 카드 1개를 지워야 한다.

## 4. 슬라이드에 수치를 쓸 때 지킬 것

1. **"골든 34문항"은 개발 중에 본 문항**이라고 한 번은 밝힌다(경과-3 하단 주석).
2. **정밀도 0.35는 하한**이다. "35%만 맞다"가 아니라 "골든이 대표 근거만 적어서 실제로는 더 높다"는 뜻이다.
3. **27~29처럼 범위로 쓴다.** 같은 설정을 두 번 돌려 나온 값이다.
4. **답변 품질(0/128, 35/36)은 답변 로직 수정 전 값이다.** 발표 전에 같은 판독을 다시 해서 바꿔 쓴다.
5. 라우터 수치는 **홀드아웃 2(15/16)만 깨끗한 값**이다. 일상 표현 20/20은 프롬프트를 쓰기 전에 본 문항이라 슬라이드에서 빼는 편이 안전하다.
6. 질문셋·기대값·판독을 Claude가 만들었으므로, 필요하면 "팀 검수 전"을 각주로 넣는다.
