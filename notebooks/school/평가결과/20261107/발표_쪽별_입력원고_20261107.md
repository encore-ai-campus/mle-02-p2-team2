# 발표 쪽별 입력 원고 (미리캔버스 40쪽 캔버스 기준, 2026-11-07)

- 대상 캔버스: 「교육시설 감염병 근거 Q&A 발표 앞부분- 복사 for Claude」(40쪽, 읽기만 했고 **수정하지 않았다**). 연결된 편집 도구는 승우 님이 만든 기존 디자인의 쪽 추가·수정을 허용하지 않아서, 이 문서를 보고 직접 입력하는 방식이다.
- 구성 근거: [슬라이드 구성안 v4](발표_슬라이드_구성_제안_20261107.md), 내용 근거: [로직 부품 정리](질문에서_답변까지_로직부품_정리_20261107.md). 수치 출처는 쪽마다 적었다.
- 기존 1~12쪽(표지·목차·배경·개요·구조도·스키마)은 건드리지 않는다.

## 0. 입력 규칙

### 0-1. 템플릿 쪽 번호 (40쪽 캔버스 기준, 구성안 v4보다 +2)

| 번호 | 레이아웃 | 이 문서의 약칭 |
|---|---|---|
| 28 | 아이콘 4칸(2×2) | **T4** |
| 29 | 아이콘 3칸(원형 아이콘) | **T3** |
| 30 | 아이콘 6칸(카드 2열×3행) | **T6** |
| 31 | 이미지 + 수치 2개 | **TI** |
| 32 | 이미지 3칸 | (미사용) |
| 33 | 게이지 2개 + 꺾은선 차트 | **TG** |
| 34 | 4×4 표 + 레이더 차트 | (미사용) |
| 35 | 5열×5행 표 | **TB** |
| 36 | 순환 4단계 | (미사용) |
| 37 | 타임라인 4단계 | **TL** |
| 38 | 역할분담(4명 카드) | 그대로 사용(3명으로) |

- 새 쪽은 위 템플릿 쪽을 **복제**해서 만든다. 복제 후 맨 위 작은 글(예: "아이콘 핵심을 전달하는 레이아웃")을 반드시 **구분 이름**(예: "기술 | Skills")으로 바꾼다.
- 이미 제목만 있는 기존 쪽(17·18·22·24·26·27)은 **템플릿을 복제한 뒤 같은 제목을 넣고**, 빈 제목 쪽을 대신하면 된다(지우는 것은 승우 님 판단).
- 13~15쪽은 스키마 쪽 복사본이라 내용이 없다. 아래 새 쪽으로 대체한다(지울지는 승우 님 판단).

### 0-2. 글자 수 한도 (글자 폭 ≈ 글자 크기로 추정한 값. 입력 후 넘침을 눈으로 확인)

| 칸 | 한도 |
|---|---|
| 제목(64px) | **15자**, 한 줄. 더 길면 상자 가로를 늘린다(27쪽이 이미 1,228px) |
| 구분 이름(32px) | 21자 |
| T4 키워드(40px) / 본문(26.7px) | 10자 / 3줄×15자 (≈40자) |

| T6 키워드(32px) / 본문 | 17자 / 점(·)으로 시작하는 2줄, 줄당 21자 |
| TI 제목 / 본문 / 수치 / 라벨 | 19자 / 약 150자 / 4자(80px) / 7자 |
| TG 제목 / 설명 | 13자 / 32자. 게이지 숫자·글, 차트 값은 편집 화면에서 직접 |
| TB 머리글 / 칸 | 10자 / 한 줄 11자, **2줄 22자**까지 |

- 한도를 넘는 내용은 슬라이드에 넣지 않고 **발표 멘트**에 둔다. 아래 쪽마다 "멘트"가 그 자리다.
- 쪽에 없는 칸(예: T3의 오른쪽 위 괄호 글)은 비워 두지 말고 아래 원고대로 넣거나 지운다.

### 0-3. 표시 약속

- **[확인]** 승우 님이 정해야 하거나 측정 전이라 비워 둔 값. 슬라이드에 그대로 쓰지 않는다.
- **(1인)** 사람 확인 전 단독 채점·주석 값. 각주에 "1인 채점"을 꼭 쓴다.

## 1. 최종 쪽 순서 (전체 46쪽)

`기존`은 이미 있는 쪽, `＋`는 새로 만드는 쪽이다. 번호는 40쪽 캔버스 기준이고 새 쪽을 끼우면 뒤 번호가 밀린다.

| 장 | 순서 |
|---|---|
| 01~02 | 1 표지 · 2 목차 · 3~7 배경 · 8~9 개요 (기존, 그대로) |
| 03 구조 | 10 구분 · 11 구조도 · 12 스키마 · **＋N1** LLM은 세 곳만 (T3) |
| 04 기술 | 16 구분 · **17**(T L) 원문이 지식그래프가 되기까지 · **＋N2** 질문 이해 (T6) · **＋N3** 찾기 (T4) · **＋N4** 거르고 줄 세우기 (TL) · **＋N5** 판단형 답변 (T4) · **＋N6** 줄 단위 검사 (T6) · **18**(TB) 사용 기술 |
| 05 시연 | 19 구분 · **＋N7** 개선 전과 후 (TB) · **＋N8** 화면 (TI) · 20 (기존, 쿼리·cypher 시각화) |
| 06 발전 경과 | 21 구분 · **22**(T3) 개요 · **＋N9** 어떻게 쟀나 (TB) · [적재] **＋N10** (T6) · **＋N11** (TB) · **＋N12** (TG) · [검색] **＋N13** (TG) · **＋N14** (TG) · **＋N15** (T4) · [답변] **＋N16** (TL) · **＋N17** (TG) · **＋N18** (TB) |
| 07 한계·기대 | 23 구분 · **24**(T6) 한계 · **＋N19** 기대 효과 (T4) |
| 08 발전 방향 | 25 구분 · **26**(T4) 질병 확대 · **27**(T3) 서비스 자체 개선 |
| 마무리 | **38** 역할분담(3명) · 39 Q&A · 40 감사 |

- 템플릿 원본 28~37쪽은 복제한 뒤 쓰지 않으면 지우거나 맨 뒤로 보내면 된다.
- 46쪽은 20분에 많다. **발표 모드에서 숨길 쪽**(→ 41쪽): 20, N10, N15, N16, 38. 40쪽 이하로 더 줄이려면 27 또는 N19를 숨긴다. 시간 배분은 [구성안 v4 3장](발표_슬라이드_구성_제안_20261107.md)의 20분 표를 따른다.

- 11쪽 구조도는 기존 그림이다. 흐름이 바뀌었으니 확인해 주세요: 판단 기준 원문 조회가 Tool 실행과 동시에 돌고, 근거 선별(LLM) 단계가 있어야 한다.

## 3. 04 기술

### 17 — 템플릿 TL 복제 후 기존 제목 "원문이 지식그래프가 되기까지" 입력

| 단계 | 이름 | 본문 |
|---|---|---|
| 1단계 | 원문 변환 | 공식 PDF를 Markdown으로 바꾼다 |
| 2단계 | 청크 | 표는 행 단위, 본문은 항목 묶음. 학교 청크 1,289개 |
| 3단계 | 행동 추출 | 표 행에서 LLM이 추출, 사람 검수(표 64개·544행). 행동 438개 |
| 4단계 | 그래프 적재 | Neo4j 그래프 + 단어 색인 + 벡터 색인(1,536차원) |

- 멘트: 표는 행 하나가 청크 하나. 행동은 "누가·언제·무엇을". 그래프는 문서–청크–행동–(역할·개념·질병). 본문은 행동 추출을 하지 않는다(설계 한계, 한계 쪽에서 다시 말함).
- 근거: 구성안 v4 04 기술 17, 총정리, progress 11/06 이행 기록.

### N2 — 템플릿 T6 복제, 17쪽 뒤

제목 `① 질문을 이해합니다` / 구분 이름 `기술 | Skills`

| 카드 | 키워드 | 줄1 | 줄2 |
|---|---|---|---|
| 1 | 범위·의도 | · 대응·인사·범위 밖을 구분 | · 의도는 최대 3개로 분해 |
| 2 | 하위 질문 | · 의도별로 따로 묻는 질문 | · 일상어를 문서 용어로 변환 |
| 3 | 문서 용어 문장 | · 개별 사례를 뺀 개념 문장 | · 예: 감염병별 등교중지 기간 |
| 4 | 상황 | · 질병·확진 여부·인원·범위 | · 질문자 역할 |
| 5 | 확인 항목 | · 신고 대상·급수·유행의심 | · 신고의무자·벌칙·등교중지 |
| 6 | 실패 대비 | · 형식 위반·시간 초과 시 | · 규칙 분류기로 되돌림 |

- 멘트: 라우터(LLM)는 선택지 안에서만 답한다. 질병·역할 이름은 사전으로만 인식해 LLM이 없는 ID를 만들 수 없다. LLM이 빠뜨린 확인 항목은 질문 낱말로 코드가 보탠다(예: "신고" → 신고 의무자). 범위 밖(진단·처방·잡담)은 Tool 없이 바로 안내한다.
- 근거: 부품 정리 2장 ②.

### N3 — 템플릿 T4 복제

제목 `② 네 갈래로 찾습니다`

| 칸 | 키워드 | 본문 |
|---|---|---|
| 좌상 | hybrid 검색 | 단어(fulltext)+vector를 순위로 합침, 질문 두 개로 검색 |
| 우상 | 그래프 확장 | 찾은 청크 → 행동 → 담당 역할·개념·질병 |
| 좌하 | 역할 직접 조회 | 질문 속 역할의 행동을 그래프에서 바로 가져옴 |
| 우하 | 판단 기준 조회 | 신고 대상 목록·유행의심 기준·벌칙 원문을 동시에 조회 |

- 멘트: 두 질문 = 원 질문 + 개념 수준 문서 용어 문장. 두 결과는 점수가 아니라 순위(RRF)로 합친다. 후보는 30개, 조치어(휴업 등)가 있으면 최대 64개. 예시(사례 1건): "성홍열도 학교장이 신고해야 하나요?"로는 신고 대상 목록 청크가 60위, 문서 용어 질문으로는 6~10위. 판단 기준 조회는 정해 둔 원문 패턴으로 DB를 직접 찾고, 코드는 글자 대조만 한다.
- 근거: 부품 정리 3장 ⑤·③, 11/07 진단 기록.

### N4 — 템플릿 TL 복제

제목 `③ 거르고 줄 세웁니다`

| 단계 | 이름 | 본문 |
|---|---|---|
| 1단계 | 안전장치 | 허용 문서·쪽수·다른 질병·조치 불일치는 제외 |
| 2단계 | 점수표 | 핵심어·역할·단계·질병 일치로 점수를 매김 |
| 3단계 | 번갈아 뽑기 | 역할·문서가 상위를 독차지하지 않게 16개 선택 |
| 4단계 | 근거 선별 | 카드 36개 중 번호로만 최대 10개(LLM) |

- 멘트: 점수표는 후보를 줄이는 용도이지 의미 판정이 아니다. 근거 선별은 직접 답·적용 조건·질문 전제 반박 근거를 고르고, 판단 기준 근거는 항상 남긴다. 핵심 구절은 코드가 원문 대조. 근거 선별 상한 10은 사례를 보고 6 → 8 → 10으로 올린 값이다(상한 비교 실험은 없음).
- 근거: 부품 정리 4장, 상한 표(6장).

### N5 — 템플릿 T4 복제

제목 `④ 근거로 판단해 답합니다`

| 칸 | 키워드 | 본문 |
|---|---|---|
| 좌상 | 답변 형식 | 결론 → 상황 판단 → 지금 할 일 → 이후 할 일 → 신고·법적 사항 |
| 우상 | 적용 판단 | 규칙 근거에 질문 상황을 대입, 근거 번호 필수 |
| 좌하 | 하지 않는 것 | 신고 주체 바꾸기, 예시를 의무로 쓰기 |
| 우하 | 모르는 부분 | 근거로 답 못한 부분은 "확인하지 못한 부분"으로 밝힘 |

- 멘트: 적용 판단 예: "코로나19는 학교장 신고 대상 목록에 없습니다[2]". 질문에 판단할 사실이 빠졌으면 "같은 반이면 …, 아니면 …"으로 나눠 쓴다. 보건소·의료기관이 하는 조치를 학교 일로 쓰지 않는다.
- 근거: 부품 정리 5장 ⑪.

제목 `⑤ 모든 줄을 대조합니다`

| 카드 | 키워드 | 줄1 | 줄2 |
