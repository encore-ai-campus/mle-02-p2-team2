# 발표 쪽별 입력 원고 (미리캔버스 40쪽 캔버스 기준, 2026-11-07)

- 대상 캔버스: 「교육시설 감염병 근거 Q&A 발표 앞부분- 복사 for Claude」(40쪽, 읽기만 했고 **수정하지 않았다**). 연결된 편집 도구는 승우 님이 만든 기존 디자인의 쪽 추가·수정을 허용하지 않아서, 이 문서를 보고 직접 입력하는 방식이다.
- 구성 근거: [슬라이드 구성안 v4](발표_슬라이드_구성_제안_20261107.md), 내용 근거: [로직 부품 정리](질문에서_답변까지_로직부품_정리_20261107.md). 수치 출처는 쪽마다 적었다.
- 기존 1~12쪽(표지·목차·배경·개요·구조도·스키마)은 건드리지 않는다.

- 쪽에 없는 칸(예: T3의 오른쪽 위 괄호 글)은 비워 두지 말고 아래 원고대로 넣거나 지운다.

### 0-3. 표시 약속

- **[확인]** 승우 님이 정해야 하거나 측정 전이라 비워 둔 값. 슬라이드에 그대로 쓰지 않는다.
- **(1인)** 사람 확인 전 단독 채점·주석 값. 각주에 "1인 채점"을 꼭 쓴다.

### 0-4. 쪽마다 쓰는 형식과 용어 풀이 (대본이 불친절하다는 지적 반영)

쪽마다 다음 순서로 쓴다. **기술·시연·발전 경과·한계·발전 방향 쪽에 적용했다.** (1~12쪽과 38쪽 카드 문구는 기존 그대로)

1. 이 쪽에서 청중이 가져갈 **한 문장**
2. 슬라이드에 넣을 글(칸별)
3. **바뀐 것 / 왜 그런지**를 표로(숫자만 있는 쪽에는 원인을 반드시 붙인다)
4. **발표 대본**: 줄임말 없이 그대로 읽을 수 있는 문장으로. 용어는 처음 나올 때 한 번 풀어 말한다
5. 질문이 나올 때 쓸 용어 풀이·한계·근거 파일

| 용어 | 대본에서 이렇게 말한다 |
|---|---|
| 청킹·청크 | 원문 PDF를 검색할 수 있는 조각으로 자르는 일 / 그 조각 |
| Hit@k | 정답이 들어 있는 조각이 검색 결과 상위 k개 안에 있는 질문 수 |
| MRR@10 | 정답이 처음 나온 순위의 역수를 질문마다 구해 평균한 값. 1에 가까울수록 정답이 위쪽 |
| hybrid 검색 | 단어 기반(fulltext)과 vector를 합친 검색 |
| 골든셋 | 정답 근거를 미리 적어 둔 평가용 질문 40개(정답 청크가 있는 34개로 검색을 잼) |
| 정밀도·재현율 | 찾은 것 중 맞은 비율 / 있어야 할 것 중 찾은 비율 |

## 1. 최종 쪽 순서 (전체 46쪽, N10 제외)

`기존`은 이미 있는 쪽, `＋`는 새로 만드는 쪽이다. 번호는 40쪽 캔버스 기준이고 새 쪽을 끼우면 뒤 번호가 밀린다.

| 장 | 순서 |
|---|---|
| 01~02 | 1 표지 · 2 목차 · 3~7 배경 · 8~9 개요 (기존, 그대로) |
| 03 구조 | 10 구분 · 11 구조도 · 12 스키마 · **＋N1** LLM은 세 곳만 (T3) |
| 04 기술 | 16 구분 · **17**(T L) 원문이 지식그래프가 되기까지 · **＋N2** 질문 이해 (T6) · **＋N3** 찾기 (T4) · **＋N4** 거르고 줄 세우기 (TL) · **＋N5** 판단형 답변 (T4) · **＋N6** 줄 단위 검사 (T6) · **18**(TB) 사용 기술 |
| 05 시연 | 19 구분 · **＋N7** 개선 전과 후 (TB) · **＋N8** 화면 (TI) · 20 (기존, 쿼리·cypher 시각화) |
| 06 발전 경과 | 21 구분 · **22**(T5) 개요 · **＋N9** 어떻게 쟀나 (TB) · [청킹/적재] **＋N11** (TB) · **＋N12** (TG) · [검색] **＋N13** (TG) · **＋N14** (TG) · **＋N15** (T4) · [답변] **＋N16** (TB, 6번의 개선) · **＋N17** (TG) · **＋N20** (TG, 2026 지침) · **＋N18** (TB) |
| 07 한계·기대 | 23 구분 · **24**(T6) 한계 · **＋N19** 기대 효과 (T4) |
| 08 발전 방향 | 25 구분 · **26**(T4) 질병 확대 · **27**(T3) 서비스 자체 개선 |
| 마무리 | **38** 역할분담(3명) · 39 Q&A · 40 감사 |

- 템플릿 원본 28~37쪽은 복제한 뒤 쓰지 않으면 지우거나 맨 뒤로 보내면 된다.
- 46쪽은 20분에 많다. **발표 모드에서 숨길 쪽**(N10은 쓰지 않음): 20, N15, 38(→ 43쪽). N16은 답변 품질 6단계 개선이라 이제 숨기지 않는다. 40쪽 이하로 줄이려면 27, N19, N18 중 둘을 더 숨긴다. 시간 배분은 [구성안 v4 3장](발표_슬라이드_구성_제안_20261107.md)의 20분 표를 따른다.

### N1 — 템플릿 T3 복제, 12쪽 뒤

| 칸 | 입력 |
|---|---|
| 구분 이름 | 구조 \| Structure |
| 제목 | LLM은 세 곳만 씁니다 |
| 오른쪽 위 글 | 근거는 코드가 검증 |
| 카드1 키워드 / 본문 | 질문 이해 / 범위·의도·상황·확인 항목을 정해진 형식으로만 출력 |
| 카드2 키워드 / 본문 | 근거 선별 / 카드 번호 중에서만 최대 10개 선택, 핵심 구절은 코드가 원문 대조 |
| 카드3 키워드 / 본문 | 답변 작성 / 근거에 있는 말로 판단해 쓰고 모든 줄을 코드가 근거와 대조 |

**한 문장:** "LLM은 해석하고 고르고 쓰지만, 근거를 만들 수는 없고 결과는 코드가 원문과 대조한다."

**발표 대본**

1. "이 서비스에서 LLM은 세 곳에서만 일합니다. 질문을 이해할 때, 근거를 고를 때, 답변을 쓸 때입니다."
2. "질문 이해는 정해진 형식으로만 답해야 하고, 근거 선별은 카드 번호 중에서만 최대 10개를 고르고, 답변은 고른 근거에 있는 말로만 판단해서 씁니다. 그러니 LLM이 근거를 새로 만들 수는 없습니다."
3. "그리고 LLM이 낸 결과는 코드가 다시 원문과 대조합니다. 대조를 통과한 것만 화면에 나갑니다."

**질문이 나오면**

- 질문당 LLM 호출은 3회이고, 답변 첫 줄이 검사에 걸리면 1회 더 호출한다. 세 곳 모두 gpt-6-luna다.
- 근거: 부품 정리 0장·7장.
- 11쪽 구조도는 기존 그림이다. 흐름이 바뀌었으니 확인해 주세요: 판단 기준 원문 조회가 Tool 실행과 동시에 돌고, 근거 선별(LLM) 단계가 있어야 한다.

## 3. 04 기술

### 17 — 템플릿 TL 복제 후 기존 제목 "원문이 지식그래프가 되기까지" 입력

| 단계 | 이름 | 본문 |
|---|---|---|
| 1단계 | 원문 변환 | 공식 PDF를 Markdown으로 바꾼다 |
| 2단계 | 청크 | 표는 행 단위, 본문은 항목 묶음. 학교 청크 1,289개 |
| 3단계 | 행동 추출 | 표 행에서 LLM이 추출, 사람 검수(표 64개·544행). 행동 438개 |
| 4단계 | 그래프 적재 | Neo4j 그래프 + 단어 색인 + 벡터 색인(1,536차원) |

**한 문장:** "공식 PDF가 청크와 행동을 거쳐 Neo4j 지식그래프와 검색 색인이 된다."

**발표 대본**

1. "원문이 지식그래프가 되기까지 네 단계를 거칩니다. 먼저 공식 PDF를 Markdown으로 바꾸고, 검색할 수 있는 단위인 청크로 자릅니다."
2. "표는 행 하나가 청크 하나이고, 본문은 항목을 묶어서 자릅니다. 학교 자료는 청크가 모두 1,289개입니다."
3. "표 행에서는 LLM으로 학교 행동을 추출했고, 사람이 표 64개·544행의 위치를 원문과 대조해 검수했습니다. 행동은 '누가, 언제, 무엇을 하는가' 단위로 438개입니다."
4. "이것을 Neo4j에 문서, 청크, 행동, 그리고 역할·개념·질병이 이어진 그래프로 적재하고, 단어 검색용 색인과 vector 검색용 색인(1,536차원)을 함께 만들었습니다."
5. "한 가지 한계가 있습니다. 본문 글은 행동 추출을 하지 않았습니다. 한계 쪽에서 다시 말씀드리겠습니다."

**질문이 나오면**

- 행동 추출에 쓴 모델명은 **[확인]**.
- 근거: 구성안 v4 04 기술 17, 총정리, progress 11/06 이행 기록.

### N2 — 템플릿 T6 복제, 17쪽 뒤

제목 `① 질문을 이해합니다` / 구분 이름 `기술 | Skills`

|---|---|---|---|

| 2 | 하위 질문 | · 의도별로 따로 묻는 질문 | · 일상어를 문서 용어로 변환 |
| 3 | 문서 용어 문장 | · 개별 사례를 뺀 개념 문장 | · 예: 감염병별 등교중지 기간 |
| 4 | 상황 | · 질병·확진 여부·인원·범위 | · 질문자 역할 |

| 6 | 실패 대비 | · 형식 위반·시간 초과 시 | · 규칙 분류기로 되돌림 |

**한 문장:** "LLM이 질문을 정해진 형식으로 풀어 주고, 실패하면 규칙으로 되돌아간다."

**발표 대본**

1. "질문이 들어오면 먼저 LLM이 질문을 이해합니다. 이 단계를 라우터라고 부릅니다."
2. "학교 감염병 대응 질문인지, 인사나 범위 밖(진단·처방·잡담) 질문인지부터 나눕니다. 범위 밖이면 검색 없이 바로 안내합니다. 대응 질문이면 안에 든 의도를 최대 세 개로 나눕니다."
3. "의도마다 따로 물어볼 하위 질문을 만들고, 일상어를 문서에서 쓰는 용어로 바꾼 '문서 용어 문장'도 만듭니다. 학생 한 명의 사례는 빼고 '감염병별 등교중지 기간'처럼 개념만 남긴 문장입니다."
4. "질병, 확진 여부, 인원, 범위, 질문하는 사람의 역할 같은 상황도 뽑고, 신고 대상인지·급수·유행의심 기준·신고 의무자·벌칙·등교중지처럼 꼭 확인해야 할 항목도 뽑습니다."
5. "LLM은 정해진 선택지 안에서만 답하고, 질병과 역할 이름은 사전으로만 인식합니다. 그래서 없는 이름을 만들 수 없습니다. 형식을 어기거나 시간이 지나면 규칙 분류기로 되돌립니다."

**질문이 나오면**

- LLM이 빠뜨린 확인 항목은 질문 낱말로 코드가 보탠다(예: "신고"가 있으면 신고 의무자 확인).
- 근거: 부품 정리 2장 ②.

### N3 — 템플릿 T4 복제

제목 `② 네 갈래로 찾습니다`

| 칸 | 키워드 | 본문 |
|---|---|---|
| 좌상 | hybrid 검색 | 단어(fulltext)+vector를 순위로 합침, 질문 두 개로 검색 |
