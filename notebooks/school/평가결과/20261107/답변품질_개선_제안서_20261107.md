# 답변 품질 개선 제안서 — "근거 나열"에서 "근거로 판단해 주는 답변"으로 (2026-11-07)

대상: 주승우(메인·UI). 팀 공유용으로도 쓸 수 있게 썼다. 발표 11/09.

## 0. 한 줄 요약

필요한 정보는 DB에 거의 다 있다. 그런데 지금 시스템은 **질문 속 상황(질병·인원·질문자 역할)을 규칙에 대입하는 단계가 없고**, 허용 문서가 5종으로 묶여 있다. 그리고 실패하면 **내부 문구가 섞인 템플릿**을 낸다. 그래서 "검토해서 답하는" 답변이 나올 수 없다.
- 고칠 것:
  - ① 상황 해석
  - ② 확인 항목 조회(신고 대상·대응 단계·신고 주체·미신고 결과)
  - ③ 상황형 답변 형식
  - ④ 실패 처리
  - ⑤ 허용 문서 확대
- 예상 비용: LLM 호출 추가 0~1회. 응답 시간은 +1~2초로 보지만 아직 재지 않았다(추정).

## 1. 재현 (로컬, 실DB 읽기·실LLM, 2026-11-07)

`scratchpad/trace_two.py`로 메인 그래프를 그대로 실행했다. 허용 문서는 UI 기본값(`EVALUATED_DOCUMENTS` 5종)이다.

### 질문 1 "전교생 중 5명 코로나 확진인데, 교장이 해야 할 일은?"
- 라우터: ACTION 단독. action_search만 호출했다. 질병 분류나 법령은 묻지 않았다.
- 근거 선별: 18 → 3개(경기 165쪽 학교장 2단계, 164쪽 2단계 주요활동, 165쪽 '총괄'). coverage는 PARTIAL로, "5명일 때 단계·코로나 기준 확인 안 됨"이라고 판정했다.
- 답변: 로컬에서는 LLM 답변이 나왔지만, 그 내용도 "신고가 필요한 법정감염병인 경우 신고"를 **조건을 판단하지 않은 채 그대로 옮긴 것**이다.
  - 화면(Streamlit)에서 템플릿 형식이 나온 이유는 확인하지 못했다. 로컬에서는 다듬기가 동작했다.
  - 배포본의 OpenAI 키, 토글, 예외를 개발자 화면 기록으로 확인해야 한다.
- **답에 필요한 원문은 DB에 있다:**
  - 학교장 신고 대상 8종(콜레라·장티푸스·파라티푸스·세균성이질·장출혈성대장균·A형간염·홍역·결핵): 교육부 59쪽, 경기 164쪽 — 허용 문서
  - 법 제12조 신고의무는 "제1급~제3급감염병": 법령 19쪽 — 허용 문서
  - 코로나19는 "제4급감염병": `kdca_covid19_2026` 3·39쪽 — **허용 목록 밖**
  - 유행의심 기준 "동일 학급 2명 이상 등 → 제3단계 격상": 교육부 62쪽 — 허용 문서
  - 결론: "코로나19는 학교장의 보건소 신고 대상이 아니다. 교육청 보고와 유행의심 판단에 따른 3단계 대응을 한다"는 근거만으로 답할 수 있었다.

### 질문 2 "내가 담임이고 홍역이 한 반에 몇 명씩 유행하는 것 같은데, 신고해야 할까? 안 하면 어떻게 돼?"
- 라우터: ACTION + LEGAL로 잘 나눴다.
- action_search는 PARTIAL로 끝났다. legal_search는 **NO_EVIDENCE**("처벌" 하위 질문)였다.
- 근거 선별: 22 → 3개. coverage는 1번 PARTIAL, 2번(처벌) NONE.
- 작성기: 첫 줄 "담임교사는 … 보건소에 신고해야 합니다"가 **주체 검사에 걸렸다.** 원문 주체는 "학교[담당교사]"이므로 올바른 차단이다. 그 결과 **답변 전체가 템플릿으로 대체됐다.**
- 템플릿에는 "원문 인용 Finding은…", "답 카드가 없거나…" 같은 **내부 경고문이 사용자에게 그대로 노출됐다.**
- **답에 필요한 원문:**
  - 홍역은 학교장 신고 대상 8종에 포함: 교육부 59쪽
  - 동일 학급 2명 이상이면 유행의심 → 3단계: 교육부 62쪽
  - 담임교사 3단계 역할(매일 추가 발생 파악, 1교시 후 학년부장 보고, 보호자 안내·진료, 등교중지, NEIS 등록): 경기 167쪽
  - 신고의무자는 학교의 관리인·대표자: 법 제12조①
  - 신고의무자가 아니어도 의심자를 발견하면 보건소장에게 알려야 함: 제12조②
  - 홍역 의심환자 발생 시 진료 안내·보건소 신고: 홍역 지침 93쪽
  - **미신고 벌칙** "제12조제1항 신고를 게을리한 자 … 200만원 이하 벌금": `kdca_respiratory_2026` 34쪽 — **허용 목록 밖**
- 참고: 제미나이 답변은 "학교장 500만원 이하 벌금"이라고 했다. 우리 자료에서 500만원은 의사 등(제11조) 위반이고, 제12조 관리인 미신고는 200만원이다. **근거 기반으로 제대로 답하면 우리가 더 정확할 수 있다.** 발표 포인트로 쓸 수 있다.

## 2. 원인 — 왜 이런 답이 나오는가

| # | 원인 | Q1 | Q2 | 근거(사실) |
|---|---|---|---|---|
| A | **상황 적용 단계가 없다.** 파이프라인이 "근거 찾기 → 근거 옮기기"뿐이다. 원문의 조건("신고가 필요한 법정감염병인 경우")을 질문 사실(코로나·5명)에 대입하지 않는다. 오히려 "단계를 판정하지 않는다"를 원칙으로 경고문까지 붙였다 | ● | ● | Tool 경고 "현재 상황의 단계를 판정한 것이 아니다" |
| B | **암묵적 확인 항목을 묻지 않는다.** 라우터는 사용자가 쓴 질문만 나눈다. 답하려면 꼭 확인해야 하는 사실(질병 등급·신고 대상 여부, 인원 → 단계, 질문자 역할의 의무)을 하위 질문으로 만들지 않아 검색·선별 대상이 아니다 | ● | ● | 라우터 sub_questions·search_queries |
| C | **허용 문서가 5종이다.** 코로나19·호흡기(벌칙 요약)·인플루엔자 지침이 DB에 있어도 UI 기본 허용 목록 밖이다 | ● | ● | `EVALUATED_DOCUMENTS`, DB 문서 10종 |
| D | **Tool 칸막이.** "처벌"은 legal_search만 찾는다. 법령은 9청크라 벌칙 조항이 없고, 벌칙 요약은 호흡기 지침에 있다 | | ● | legal_search NO_EVIDENCE |
| E | **답변 형식이 역할별 나열이다.** "결론 → 내 할 일 → 학교가 할 일 → 법적 사항 → 확인할 것" 같은 상황형 구성이 아니다. 최대 12줄 제한과 "근거에 있는 것만 옮김" 규칙 때문에 판단·우선순위 문장을 쓸 수 없다 | ● | ● | SYSTEM_PROMPT 규칙 1·3·7 |
| F | **실패 처리가 사용자 화면을 망친다.** 첫 줄 하나가 걸리면 템플릿으로 바뀐다. 템플릿은 Tool 내부 경고·원문 조각을 그대로 보인다 | (화면) | ● | compose_text, 경고 노출 |
| G | **평가가 사용자 체감과 따로 놀았다.** 골든 40은 "정답 청크 인용"을 재므로, 상황형 질문의 답변 유용성을 재지 못했다 | ● | ● | 11/05~11/07 지표 |

정리하면 **검색이 못 찾은 문제보다, 찾을 수 있는 근거를 연결해 판단하는 단계와 보여 주는 형식이 없는 문제**가 크다.

## 3. 해결 원칙 (바꾸는 것과 지키는 것)

**바꾸는 것: "근거 기반 적용 판단"을 허용한다.**
- 원문 규칙과 질문의 사실을 대입한 결론은 쓴다. 예: "코로나19는 제4급이므로 제12조(제1~3급) 신고의무 대상이 아닙니다."
- 단, 그 줄에 **규칙 근거 [n]**과 **대입한 질문 사실**을 함께 밝힌다.
- 질문에 판단할 사실이 없으면(예: 5명이 같은 반인지) 판단하지 않는다. "같은 반이면 ~, 아니면 ~"으로 갈라 말하거나 확인 사항으로 남긴다.

**지키는 것:**
- 근거에 없는 사실·숫자·기관은 쓰지 않는다. 숫자·주체·강도 검사는 유지한다.
- 예시 역할을 의무로 바꾸지 않는다.
- 근거가 없으면 "이 자료로는 확인하지 못했습니다"라고 쓴다.
- 팀 합의대로 학부모 응대 예시 섹션은 넣지 않는다.

## 4. 해결 방안

### P0 (발표 전 필수)

**P0-1 상황 해석(라우터 확장, LLM 호출 추가 없음)**
- 라우터 출력에 `situation`을 더한다.
  - 질병
  - 확진/의심
  - 인원·범위(한 반, 여러 반, 전교, 모름)
  - 질문자 역할(담임, 보건교사, 교장, 모름)
  - 묻는 것(할 일, 신고, 처벌, 기간, 등교)
- `checks`도 더한다. 질문에 답하려면 확인해야 할 항목이다.
  - 신고 대상 여부
  - 대응 단계 판정
  - 질문자 역할의 의무
  - 미신고 결과
  - 등교중지 기간
- `checks`는 하위 질문처럼 근거 선별의 coverage 대상이 된다.

**P0-2 확인 항목 조회(결정적 조회, DB 읽기)**
- 확인 항목마다 고정된 근거를 찾아 Finding으로 넣는다. 질의는 허용 문서 범위 안에서만 한다.
  - 신고 대상: 학교장 신고 대상 8종 목록 청크(교육부 59쪽·경기 164쪽) + 질병 등급 청크(법령 정의·질병 지침 개요)
    - 코드는 질병명이 목록에 있는지만 대조한다. 결론은 작성기가 근거와 함께 쓴다.
  - 대응 단계: 유행의심 기준 청크(교육부 62·63쪽, 경기 164쪽)
  - 신고 주체: 법 제12조①②(법령 19쪽), 학교장 신고 방법(교육부 59쪽)
  - 미신고 결과: 벌칙 요약(호흡기 지침 34쪽), 법령 벌칙 조항(적재되면)
- 목록·기준 청크의 ID는 담당 문서(교육부·경기) 범위에서 지정한다. 다른 담당자의 문서(법령, KDCA 지침)는 텍스트 질의로 찾는다(폴더 import 금지 원칙 유지).

**P0-3 허용 문서 확대(팀 확인 필요)**
- UI 기본 허용 목록에 `kdca_covid19_2026`, `kdca_respiratory_2026`, `kdca_flu_facility_2026`, `kdca_vaccine_preventable_2026`, `kdca_hfmd_2026`을 더한다.
- 이 문서들은 이미 DB에 적재돼 있다. 담당자(송수림)에게 데모 노출이 괜찮은지 확인한다.

**P0-4 답변 형식 개편(작성기 프롬프트 + 검사)**

5장 명세대로 바꾼다. 줄 수 제한은 12줄에서 약 22줄로 늘린다.

**P0-5 실패 처리**
- (a) 사용자 화면에서 Tool 내부 경고("원문 인용 Finding은…", "답 카드가…", "'원문 강도'는…")를 없앤다. 개발자 화면에만 남긴다.
- (b) 첫 줄이 걸리면 **1회만** 문제를 알려 다시 쓰게 한다. LLM 호출은 실패할 때만 +1회다. 그래도 걸리면 "확인한 근거 요약" 형식으로 낸다. 원문 조각을 나열하지 않는다.
- (c) Streamlit Cloud에서 Q1이 템플릿으로 나온 원인(키·토글·예외)을 확인한다.

### P1 (발표 전 가능하면)

- **P1-6 근거 선별:** 확인 항목을 coverage에 넣고, 선별 상한을 8에서 10으로 올린다. 프롬프트에 "판단에 쓰는 규칙 근거(목록·기준·조문)는 질문 표현과 덜 비슷해도 고른다"를 넣는다.
- **P1-7 법령 벌칙 조항 적재:** 감염병예방법 제79조~제83조. 유종혁 담당이고 DB 쓰기 승인 절차를 따른다. 적재 전에는 호흡기 지침 34쪽 요약으로 답한다.
- **P1-8 데모 평가셋:** 상황형 질문 15개(이 두 질문 포함)와 4장 루브릭으로 개선 전후를 비교한다.
  - 질문 작성과 1차 채점은 Claude가 한다. 최종 판정은 사람이 한다.
  - 11/06에는 실사용 질문셋을 쓰지 않기로 했지만, 이번 문제는 골든셋으로는 보이지 않아서 다시 제안한다.

### P2 (발표 후)

- 후속 질문 제안 버튼(예: "등교중지 기간", "가정통신문 근거") — 화면 기능.
- 질병 지침(호흡기 등) 내 학교 관련 행동을 action_search 대상으로 편입할지 팀이 논의.

## 5. 답변 출력 형식 명세

### 5-1. 구성 (질문 유형에 따라 해당 칸만)

```
**[결론]** 질문에 대한 직접 답 1~2문장 — 예/아니요, 누가, 무엇을. 판단 근거 [n]
(질문에 판단할 사실이 빠졌으면: "~라면 …, ~라면 …"으로 갈라서)

**상황 판단**            ← 신고 대상 여부·대응 단계 등 적용 판단. 줄마다 '규칙 [n] + 질문 사실'
**지금 바로 할 일**       ← 질문자 역할 기준, 번호 순서(시간순)
**학교(다른 담당)가 할 일** ← 보건교사·학교장 등. "예시 역할" 표시 유지
**신고·법적 사항**        ← 물었거나 신고가 걸릴 때만. 벌칙은 원문 그대로의 상한만
**확인하지 못한 부분**     ← 자료에 없는 것 + 학교가 확인할 것(보건소 문의 등)
```

### 5-2. 규칙

1. 첫 줄은 결론이다. 질문이 예/아니요면 "네/아니요"로 시작하되, **본문 지침 근거**로만 정한다(시나리오 예시로 정하지 않음, 11/07 S-T03).
2. 적용 판단 줄은 "규칙(원문) [n] → 질문 사실 → 결론" 순서로 쓴다. 규칙을 줄이지 않는다.
3. 질문자 역할이 있으면(내가 담임…) "지금 바로 할 일"은 그 역할 기준으로만 쓴다. 다른 담당의 일은 다음 칸으로 보낸다. 담임이 보건소에 직접 신고한다는 식의 **주체 바꿔치기는 금지**한다(검사 유지).
4. 시나리오·다른 단계 근거는 표시한다(11/07 ③).
5. 벌칙·금액·기간 숫자는 원문 그대로 쓴다(숫자 검사 유지). 질문자 개인에게 적용되는지 근거가 없으면 "적용 대상은 학교의 장(신고의무자)이며, 담임교사 개인에 대한 조항은 자료에서 확인하지 못했습니다"처럼 범위를 밝힌다.
6. 내부 용어(Finding, Tool, 답 카드)·쪽수 나열은 본문에 쓰지 않는다. 출처는 [n]과 화면의 근거 패널로 보여 준다.
7. 공감 문장(예: "당황스러우실 것 같습니다")은 넣지 않는다. 결론부터 쓴다. 학부모 응대 문구는 팀 합의대로 쓰지 않는다.

### 5-3. 목표 답변 예시 (근거 청크 확인함. 실제 출력은 LLM 문장에 따라 달라짐)

**질문 2(홍역, 담임)** — 허용 문서 확대 전제

> **결론: 신고 대상입니다. 다만 법상 신고는 학교장이 하며, 담임선생님은 의심 학생을 발견한 즉시 보건교사·학교장에게 알리시면 됩니다.**[1][3]
>
> **상황 판단**
> - 홍역은 학교장이 교육(지원)청과 보건소에 신고해야 하는 감염병 8종에 포함됩니다.[1]
> - 같은 반에서 의심·확진 환자가 최대 잠복기 안에 2명 이상이면 '유행의심 기준'에 해당해 대응 제3단계로 올립니다. 질문하신 "한 반에 몇 명씩"은 이 기준에 해당할 수 있습니다.[2]
> - 법상 학교의 신고의무자는 학교의 관리인·대표자입니다. 신고의무자가 아니어도 의심 환자를 발견하면 보건소장에게 알려야 합니다.[3][4]
>
> **지금 바로 할 일(담임교사, 제3단계 예시 역할)**
> 1. 매일 학급 학생의 추가 발생 여부(출결·증상)를 파악하고 1교시 후 학년부장에게 보고합니다.[5]
> 2. 보호자에게 유행의심 상황을 알리고 의료기관 진료를 안내합니다. 진료 결과에 따라 등교중지를 실시합니다.[5]
> 3. 환자 발생을 나이스(NEIS)에 등록합니다.[5]
>
> **학교가 할 일**
> - 학교장은 나이스 전자결재로 교육(지원)청과 보건소에 신고합니다.[1]
> - 교내 홍역 의심환자가 생기면 의료기관 진료를 안내하고 관할 보건소에 신고합니다.[6]
>
> **신고하지 않으면**
> - 제12조제1항에 따른 신고를 게을리한 자는 200만원 이하의 벌금에 처합니다.[7] 이 조항의 신고의무자는 학교의 관리인·대표자이며, 담임교사 개인에 대한 별도 벌칙은 자료에서 확인하지 못했습니다.
>
