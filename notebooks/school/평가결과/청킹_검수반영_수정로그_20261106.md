# 청킹 전수검수 반영 — 원인·수정·회귀 기록

기준일: 2026-11-06 KST. 사용자가 원문과 대조한 주소 64개 표, 인용 이동 11건, 행동 단계 5개 근거 청크의 검수를 반영했다. 검수 문서 3개는 수정하지 않았고 SHA-256으로 보존을 확인했다. ABOUT 규칙, source_manifest, 공유 DB, 기존 골든셋, 이전 승인 행동 파일은 변경하지 않았다.

## 2. 오류별 원인과 해결

### 시나리오 질병·단계가 다른 시나리오에 상속됨 — T01~T06

- 문제: 인플루엔자 자료의 `다. 대응 3단계`가 A형간염 PDF 42~44쪽까지 이어졌다. 이 잘못된 주소로 기존 행동 54개를 대응3으로 바꾸자는 후보까지 생겼다.
- 원인: 숫자 뒤 공백·점만 인식해 `2-1.`, `2-2.`를 제목으로 인식하지 못했다. 새 시나리오의 시작에서 하위 경로가 초기화되지 않았다.
- 수정: 하이픈 번호 제목을 별도 문법으로 인식하고 형제 시나리오 경계에서 이전 소절·항목을 닫는다. 원문에 있는 `<감염병 발생 시나리오 단계 3>` 문구를 근거로 검수 결정을 뒤집는 새 추론은 하지 않았다. 검수대로 54개 행동의 미지정 값을 유지한다.

### 각주 `4)`가 주소가 됨 — T14·T19

- 문제: 표 아래 ‘격리하여 관찰하는 것’이라는 정의가 상위 주소로 들어갔다.
- 원인: `숫자)` 모양만 보고 제목으로 분류했다. 표의 `[1)2)]`, `[3)]`, `[4)]` 참조와 하단 정의 목록을 구분하지 않았다.
- 수정: 페이지 하단의 연속 번호 정의 목록과 앞선 표의 각주 참조가 함께 있는 경우 각주로 표시한다. 각주 텍스트는 삭제하지 않고, 구조 경로 갱신만 막는다. 뒤에 실제 새 소절이 나오면 각주 영역을 종료한다. 참조 없는 실제 `1) 연락`, `2) 격리` 항목은 제목으로 유지한다.

### ‘붙임’·원문자 질병 제목이 빠짐 — T42~T55

- 문제: 붙임의 해외감염병 표가 앞의 여행 주의사항·모기매개 감염병 절에 속한 것처럼 표시됐다.
- 원인: `붙임 1~4`와 `①~⑦`에 대한 문법이 없었다.
- 수정: 붙임은 앞 절의 하위 문맥을 닫는 계층으로, 원문자는 붙임 아래 형제 항목으로 처리한다. 페이지가 바뀌어도 해당 붙임을 유지한다. 원문의 `⑤ 치군구니야열` 표기는 검수대로 보존하고 별도 질병명 정규화를 섞지 않았다.

### 같은 페이지의 여러 표·도표를 공통 범위로만 표시 — T37~T41 등

- 문제: p245의 장애 학생 취약성 표와 모의훈련 표에 서로 다른 소속이 필요하지만 같은 공통 경로가 붙었다. p253 표도 실제 ‘2 해외여행 감염병 예방수칙’보다 넓은 경로만 있었다.
- 원인: 캡션을 특정하지 못하면 페이지 공통 상위 범위를 쓰는 fallback이었고, 전사 작업의 ‘후보 1/2’라는 이름으로는 정확한 위치를 복구할 수 없었다.
- 수정: 사용자가 확인한 표 ID별 경로를 검수 데이터로 저장해 적용한다. 원문 행 해시가 달라지면 검수가 낡은 것으로 보고 오류로 중단한다. ‘주소 맞음’ 37개도 함께 고정해 다른 수정에 의해 다시 바뀌지 않도록 했다.

### 작업본 제목과 원문 제목이 다름 — T37·T38·T43~T46

- 문제: ‘후보 1’ 또는 ‘표 1’이 실제 제목처럼 노출됐다.
- 원인: 작업본의 식별 제목과 공식 캡션이 분리되지 않았다. 검수 메모에는 ‘후보 1이 아니라 표 5-1’처럼 버릴 제목과 쓸 제목이 함께 있었다.
- 수정: 메모의 최종 채택 제목을 보존한다. 원문 표 제목·주소를 각각 적용하고 `working_table_title`은 추적용으로 남긴다. 잘못된 이름을 다시 선택하지 않는 실제 T37 회귀 검사를 추가했다. 공식 제목이 미확정이면 제목을 만들어내지 않고 header+row를 사용한다.

## 3. 구현 위치와 적용 순서

1. `structure.py`: 일반 문법 수정(하이픈 번호, 붙임, 원문자, 참조된 각주). 원문 전체 구조를 먼저 읽는 기존 순서는 유지.
2. `compile_chunk_reviews.py`: 사람이 작성한 3개 Markdown을 읽고 검수 스냅샷 생성. 기존 문서·기존 스냅샷을 덮어쓰지 않는다. 빈 필드와 공백 차이를 처리하며 미완성 판정은 거부한다.
3. `data/specs/school_reviewed_contexts_20261106.json`: 64개 표의 판정·주소·제목·각 표의 행 해시, 11개 인용 승인, 행동 55개의 단계 결정을 저장. 출처 문서의 경로·전체 파일 해시·메모를 포함.
4. `reviewed_context.py`: 표 ID와 행 해시를 확인하고 검수 주소 적용. 행동은 기존 chunk_id·stage를 확인한 뒤 복사본에 적용한다. 원본 후보는 변경하지 않는다.
5. `chunks.py`: 일반 구조 분석·표 위치 처리 후 검수된 문맥을 적용. 버전은 `school_structure_v3_reviewed`.
6. `chunking_regression.py`: 새 청크·추출 입력·검수 행동·후보 bundle·후보 golden·인용 이행 목록을 별도 실행 폴더로 저장한다. `school_chunks_full.ipynb`도 같은 검수 행동 함수를 사용한다.
