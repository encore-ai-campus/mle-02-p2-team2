## 1. 전달 목적과 현재 결론

사용자는 다음 두 문제를 해결하면서 **11/05 일정의 범위 안에서** 결과를 개선하고자 했다.

2. 특정 질병·조치 질문에 다른 질병, 일반 역할, 시나리오 등 주변 근거가 함께 붙는 문제.

해당 문제를 막는 규칙은 추가했다. 사용자가 직접 입력한 EKC 휴업 질문은 직접 근거 2건으로 정리됐다. 그러나 전체 골든셋을 평가하니 **정답 인용 1개 이상은 25/34 → 24/34, 전부 인용은 15/34 → 13/34로 하락**했다. 전체 개선으로 볼 수 없다.

이 문서는 Codex가 **어디를 어떻게 바꾸기로 결정했고, 왜 그렇게 했는지**와 재검토 지점을 기록한다. 성능 하락의 원인을 모두 확정한 문서는 아니다. 평가 후 그 실패에 맞춰 제품 코드를 추가 조정하지 않았다.

후속 검토에서는 질병명 오인 방지와 다른 질병 배제의 효과를 유지하면서, 정답 회수를 잃는 선별·상한 정책을 분리해서 비교하는 것이 우선이다. 아래 제안은 다음 수정의 확정 구현안이 아니다.

## 4. 결정 기록

### D01. 질병명은 단계 힌트용 문자열에서만 마스킹

**위치:** `relevance.py:43`의 `mask_disease_names()`, `action_tool.py:90`의 `plan_action_task()`.

- 이전: 기존 `plan_question()`의 단순 포함 검사에서 `유행`을 찾으면 제3단계 힌트가 생겼다.

- 결정 이유: 질병 고유명과 상황 서술을 구별하되, 사용자 상황을 모델이 추정하게 만들지 않기 위해서다.

### D02. 점수보다 먼저 명시적인 질병 불일치를 배제

**위치:** `relevance.py:23`, `:56`, `:76`, `:80`; `retrieve_action_records()`의 후보 추가·청크·근거 재조회 부분.

- 이전: 질병 일치는 점수 가산점이었다. 다른 질병이나 유사 단어만 있는 청크도 점수로 남을 수 있었다.
- 변경: 행동의 질병 ID와 행동/조건 문장, 본문 절, 질병별 표의 행을 사용해 명시적인 불일치를 제외한다.
- 질병별 표는 첫 열 머리글이 `감염병/감염병명/질병/질병명`일 때 마지막 데이터 행의 첫 칸을 우선한다. 추출 과정에서 앞의 COVID-19 절 제목이 종합표에 남은 사례가 있어 표 행을 더 구체적인 정보로 보았다.
- 일반 본문은 뒤에서부터 찾은 가장 가까운 질병 절을 사용하고, 없으면 본문/발췌에서 승인 명칭을 찾는다.
- `None`은 일반 근거, 빈 집합은 질병 표의 주제를 사전으로 확인하지 못한 경우다. 질병이 지정된 질문에서는 후자를 일반 근거로 통과시키지 않는다.
- 결정 이유: 급성 출혈성 결막염 행을 EKC 근거처럼 붙이는 일을 단순 점수 상승/하락으로 해결하기 어렵다고 판단했다.
- 승인 name/aliases만 사용하고 `review_aliases`의 `눈병`은 자동 연결하지 않는다. 짧은 영문 별칭 Flu/TB가 다른 영문 단어 내부에서 일치하는 것도 제한했다.
- 한계: 다른 질병을 설명하면서 목표 질병과 비교하는 유효 근거가 엄격한 검사로 빠질 수 있다. 사전 미등록 질병의 일반 본문은 표 행과 달리 일반 근거로 남을 수 있다. 본문의 단순 동시 언급과 실제 적용 조건을 완전히 구분하지 못한다.

- 추가한 조치 표현: `휴업`, `휴교`, `등교중지`, `소독`, `환기`, `능동감시`.
- 변경: 해당 표현이 질문에 있고 수행 역할이 감지되지 않으면, 행동/조건/절 또는 청크/발췌/절에 그 표현이 있는지 검사한다. 여러 표현은 현재 ANY 조건이다.
- 결정 이유: EKC라는 병명이 맞아도 손 씻기·안과 진료는 휴업 여부에 직접 답하지 않기 때문이다.

### D04. 검색 후보 수와 최종 출력 수를 분리

**위치:** `action_tool.py:275` 부근.

```python
candidate_k = max(12, top_k + 4)
if operation_terms:
    candidate_k = min(64, max(32, top_k * 4))
```

- 이전 기본 후보 수는 12개였다.
- 변경: 조치가 명확한 질문의 기본 후보 수를 32개로 늘렸다. 그 밖의 기본 후보 수는 12개다.
- 결정 이유: 필터가 생긴 상태에서 상위 12개가 질병 증상표로 채워지면 정답인 휴업 지침을 확보하지 못했다. 실제로 `유행성각결막염이 유행하면 휴업해야 하나요?`의 하이브리드 검색에서 이 현상을 확인하고 후보 수를 늘렸다.
- 별도 Tool 호출/재진입을 추가한 것은 아니다. 한 Action Tool의 검색 후보 확보량을 바꾼 것이다.
- 주의: `search_school_chunks(k)` 내부에서 fulltext/vector를 각각 `2*k`만큼 가져온 뒤 RRF를 한다. 후보 수 변경은 단순히 같은 목록을 더 길게 자르는 것과 완전히 같지 않다.
- 기존 `_score()` 계산과 행동 문턱 **4**는 유지했다. 이 점수는 관련성 확률로 보정된 값이 아니다.

### D05. 특정 질병·조치의 본문 직접 근거가 있으면 배경 근거를 제외

**위치:** `action_tool.py:333` 이후 `direct_quotes`, `direct_actions`, `prefer_direct_evidence`.

- 적용 조건: 질병과 operation_terms가 있고, 질문이 시나리오/모의훈련을 명시적으로 요청하지 않을 때.
- 변경: 해당 질병의 비시나리오 본문 근거가 하나라도 있으면 일반 지침·시나리오 근거를 함께 채우지 않는다.
- 결정 이유: 비권장 원칙과 예외를 이미 찾았는데, 일반 역할·휴업 검토 시나리오가 뒤에 붙어 답변을 흐리는 것을 줄이려 했다.
- 이 규칙은 **우선 정렬만 하는 것이 아니라 일부 후보를 배제**한다.
- 한계: 일반 조항이 직접 근거의 조건·예외·절차를 보완하는 경우에도 제외될 수 있다. 자연어로 '보조 근거가 불필요하다'고 판정한 것은 아니다. 후속 비교에서 독립적으로 켜고 끌 필요가 있다.

### D06. 행동과 인용을 합친 총 top-k 상한 적용 — 우선 재검토 대상

**위치:** `action_tool.py:349`와 `:350`.

이전 기본값은 행동 최대 8개에 원문 인용 최대 4개를 더해 최대 12개 Finding이었다. 다음과 같이 바꿨다.

```python
quotes = quotes[:max(1, top_k // 2)]
actions = actions[:max(0, top_k - len(quotes))]
```

- 기본 top_k=8에서 인용이 4개면 행동은 4개만 남는다. 인용이 없으면 행동은 최대 8개다.
- 결정 이유: top_k를 출력의 총 상한으로 맞추고 관련성이 낮은 근거로 개수를 채우지 않으려 했다.
- **불충분했던 판단:** 조치가 좁은 EKC 휴업 질문에서 얻은 이점을 역할 수행 목록 질문에도 같은 총량 정책으로 적용했다. 인용에 먼저 자리를 배정하는 것이 역할 행동 회수에 미치는 영향을 전체 골든 평가 전에 충분히 검증하지 못했다.
- 이번 평가에서 S-Q07의 정답 인용은 2/2→0/2가 됐다. 총량 제한이 원인이라는 통제 A/B는 아직 하지 않았으므로 원인 후보로 기록한다.

추가로 코드 처리 순서에서 확인할 점이 있다.

1. 행동 후보를 선택하고 근거를 재조회한다.
2. 그 행동들의 청크 ID로 `used`를 만든다.
3. 원문 인용 후보를 만들 때 `used`의 청크는 제외한다.
4. 그 뒤 행동 목록을 총량 상한으로 다시 자른다.

따라서 **나중에 잘릴 행동의 근거를 인용 경로에서는 이미 제외했을 수 있다.** 최종 선택 후 `used`를 다시 계산하거나 빈자리를 보충하는 처리는 없다. 이것이 실제 S-Q07 손실을 만들었는지는 별도 확인이 필요하다.

또한 `diversify()`의 역할·문서별 분산 이후 전체 행동을 앞에서 다시 자르므로, 분산 선택의 효과가 줄어들 수 있다. 원문 인용과 행동은 같은 의미 점수로 통합 정렬되지 않는다.

### D07. 질병 적용 근거가 없으면 PARTIAL로 낮춤

**위치:** `action_tool.py:380`의 `records_to_tool_result()`, 특히 `:440` 이후.

- 변경: 선택된 행동의 질병 ID, 근거 청크의 적용 질병, 인용 발췌/절의 적용 질병을 모아 질문한 질병의 포함 여부를 검사한다. 누락되면 `[미해결]`과 PARTIAL을 반환한다.
- 결정 이유: 일반 학교 지침만 확보하고 특정 질병에 대한 기준까지 확인했다고 과장하지 않기 위해서다.
- 원문 인용의 경우 청크의 다른 문장에만 등장하는 질병명으로 발췌의 적용 여부를 채우지 않도록 excerpt 인자를 추가했다. 표 행·질병 절의 맥락은 보존한다.
- 한계: **질병의 포함 여부**를 확인하는 규칙이다. 원질문의 모든 역할·단계·조건·기한을 충족하는지 검사하지 않는다. 일반 학교 행동 지침이 특정 질병에도 적절한 경우에는 지나치게 보수적일 수 있다.
- 실제로 기존 함정 문항 S-T02는 여전히 기대 PARTIAL에 대해 ANSWERED다. 의미적 충분성 검증을 완성했다고 보고하면 안 된다.

### D08. 검증·로그와 노트북 출력 보완

- `relevance_filter`: 제외된 청크/행동 ID와 `disease_mismatch`, `operation_mismatch` 이유.
- `prefer_direct_evidence`: 일반/시나리오 배경 후보를 몇 개 제외했는지.
- `chunk_*`: 검색 후보 수, 범위 내 수, 적합성 통과 수.
- 직접 질문 셀: 모듈 reload, status·tools_used·search_rounds, 질병/단계 힌트, Finding/Citation 수를 표시.
- 공통 ToolResult/QueryOutput에는 새 필드를 추가하지 않았다. trace는 내부 실행 기록이다.
- 기존 DB 검증은 청크·쪽수·발췌·관계의 실재를 확인한다. 의미 적합성 검증을 대체하지 않는다.
- 한계: 최종 총량 절단으로 사라진 행동 ID를 모두 별도의 제거 로그로 남기지는 않는다. `evidence` 로그의 수는 일부 후속 절단 전 값이다. 손실 추적을 위한 로그 보완도 검토할 수 있다.
