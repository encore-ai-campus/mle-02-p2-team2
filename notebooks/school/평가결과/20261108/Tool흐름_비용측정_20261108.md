# Tool 호출 흐름·안전장치 비용 측정 (2026-11-08)

- 질문(승우 님): "주 의도 Tool 먼저 → 부족하면 추가 Tool" 순차 구조와 Tool마다 반복하는 안전장치(허용 문서 재적용, 선정 쪽수, DB 대조)가 Tool 호출을 늘리고, 복합 탐색을 막거나 시간을 늘리지 않는가?
- 방법: 코드 동작은 바꾸지 않고, 측정 스크립트가 함수를 감싸 시간·횟수를 기록했다([tool_flow_profile.py](../tool_flow_profile.py)).
- 범위: 데모 15문항(D01~D15)과 골든 학교 40문항, 총 55문항. 이 중 Tool을 쓴 질문은 51개다.
- 조건: 화면과 같은 조립(`service.build_registry`, 4개 Tool 연결)과 같은 허용 문서(DB 문서 10종 전체). 각 1회 실행이다. DB는 읽기만 했다.
- 명령: `uv run python notebooks/school/평가결과/tool_flow_profile.py <out.json> --set all`
- 원자료: [tool_flow_profile_20261108.json](tool_flow_profile_20261108.json). 질문·상태·노드 시간·Tool 시간이 들어 있고, 답변 본문은 없다.
- 노드 시간: 그래프 기록 사이의 벽시계 간격이다. check_facts는 Tool과 동시에 돌기 때문에 여기서 0초로 보인다(대기 시간만 잡힌다).

## 2. 해석

### 2-1. "Tool 호출이 여러 번 생긴다"는 측정과 맞지 않는다
- 92%(47/51)가 Tool 1회로 끝났다.
- 재탐색은 "부족할 때 + 명시적 신호"에서만 일어나서 드물다.

### 2-2. 문제는 횟수가 아니라, 일어난 2번째 호출이 모두 헛걸음이었다는 점이다
- 법령 Tool은 사람이 만든 답 카드에 맞는 질문에만 답한다. 그래서 일반 신고 질문에서는 NO_EVIDENCE가 되고, 그동안 2.6~4.3초가 들었다.
- 그 시간의 상당 부분(약 1.8~2.6초)이 새 DB 연결이다.
- 같은 법 조문(제12조·벌칙)은 메인의 판단 기준 조회(`checks.py`)가 이미 동시에 가져오고 있었다. 4건 모두 최종 답변은 ANSWERED였다.

### 2-3. 순차 구조는 이제 비용이 된다 (가설 포함)
- 순차 구조는 공통 계약 v2.0의 결정이다("기본 1개 Tool, 근거 부족 시 추가 호출"). 그때는 주 의도만 알 수 있었다.
- 지금은 LLM 라우터가 처음부터 의도 여러 개와 의도별 하위 질문을 낸다. 그러니 보조 의도 Tool을 주 Tool이 끝난 뒤가 아니라 동시에 부를 수 있다.
- 동시에 부르면 이번 측정의 2-Tool 문항은 약 17초에서 12~14초로 줄어들 것으로 추정한다. 실측은 하지 않았다.

### 2-4. 안전장치 자체는 시간 원인이 아니다. DB 대조의 '방식'만 비싸다
- 허용 문서·선정 쪽수 재적용은 측정상 비용이 거의 없다.
- 비싼 것은 학교 행동 Tool의 DB 대조(평균 1.11초, 전체의 약 9%)다. 검증이 필요해서가 아니라 쿼리 5개를 차례로 보내서 생긴다.
- 쿼리를 합치거나 동시에 보내면 검증 강도는 그대로 두고 0.3~0.5초로 줄일 수 있을 것으로 추정한다. 실측은 하지 않았다.

### 2-5. 기능 면: "독립성 때문에 기능을 잃는가"에 대한 실제 모습
- 51문항 중 47문항의 첫 Tool이 학교 행동 Tool이다. 질병 Tool은 1회, 문서 비교 Tool은 2회만 쓰였다.
- 학교 행동 Tool이 DB 전체 문서를 hybrid 검색하기 때문에, 질병 문서 원문도 이 Tool을 통해 들어온다. 사실상 학교 행동 Tool이 공용 검색기 역할을 하고 있다.
- 법령 Tool이 덮지 못하는 판단 기준은 메인의 `checks.py`가 따로 채운다. 그래서 같은 일을 두 곳이 한다.
- 즉, Tool이 독립적이어서 호출이 늘어난 것이 아니다. 각 Tool의 담당 범위가 좁아서, 통합 단계가 하나의 Tool과 메인 보강 조회에 기대고 있다.
- 질병 Tool을 더 자주 불렀다면 답이 좋아졌을지는 측정하지 않았다.

### 2-6. 시간을 줄이려면 가장 큰 덩어리는 LLM 세 단계다
- LLM 세 단계가 67%를 차지한다.
- 안전장치·순차 구조를 모두 고쳐도 줄어드는 몫은 문항당 평균 약 1~1.5초다. 2-Tool 문항만 보면 약 4초다.

## 4. 한계
- 1회 실행이다. LLM 라우터 결과(보조 의도 유무)는 실행마다 달라질 수 있다.
- 질문셋이 학교 행동 위주다(골든 학교 40, 데모 15). 질병·법령 중심 질문 비율이 높은 실사용에서는 2-Tool 비율이 다를 수 있다.
- 노드 시간에는 화면 콜백과 기록 비용이 조금 섞여 있다.
- 안전장치가 필요한 근거를 지운 사례(재현율 손실)는 이번에 재지 않았다. 학교 행동 Tool 기록의 `relevance_filter`(rejected_hits)로 따로 볼 수 있다.
- 개선 효과는 모두 추정이다.
