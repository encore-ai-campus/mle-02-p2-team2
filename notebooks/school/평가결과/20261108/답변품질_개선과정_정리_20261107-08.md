# 답변 품질 개선 과정 정리 (2026-11-07 ~ 11-08)

이틀 동안 한 답변 품질 개선 6단계를 일어난 순서대로 정리한다. 단계마다 **문제 상황 → 원인 → 해결책 → 결과**로 적는다.
- 숫자는 각 단계 상세 기록에서 가져왔다. 별도 표시가 없으면 실DB 읽기·실LLM으로 1회 실행한 값이다.
- 질문셋 판정은 Claude가 했다(사람 확인 전).
- 사실(측정값)과 해석·가설은 나눠 적는다.

## 1. 신고 질문 라우팅 규칙 (11/06 밤 ~ 11/07 새벽)

**문제 상황**
- 골든 S-Q03 "성홍열도 학교장이 보건소에 신고해야 하나요?"가 법령 Tool로만 가서 근거 부족으로 끝났다.
- 같은 유형("결핵 학교장 신고", "홍역 신고 공문")도 같은 결과였다.

**원인**
- 정답 근거 2개는 모두 경기도 가이드북에 있다("신고가 필요한 법정감염병인 경우 학교장은 관할 보건소장에게 신고").
- 법령 Tool은 사람이 만든 답 카드에 맞는 질문에만 답한다. 법령만 부르면 카드가 없을 때 막다른 길이 된다.
- 학교 행동 Tool을 먼저 부르면 "법정 신고 의무는 학교 문서만으로 확정할 수 없음"을 남긴다. 그러면 법령 Tool이 이어서 호출된다.
- 같이 발견한 사실: 학교장 신고 대상 8종 목록 청크는 질문 표현에 따라 순위가 크게 달랐다.
  - 병명을 넣은 질문: 60위
  - 개념 수준 질문("학교장이 신고해야 하는 법정감염병 종류"): 6~10위

**해결책**
- 라우터 규칙:
  - 학교의 신고 의무만 묻고 법을 말하지 않음 → 학교 행동(주) + 법령(보조)
  - 법·처벌을 직접 물음 → 법령만
  - 신고 공문 절차를 물음 → 학교 행동만
- LLM 실패 시 쓰는 규칙 분류기에도 같은 원칙을 적용했다.
- 측정 스크립트 오류를 고쳤다. 호출이 2회일 때 마지막 Tool이 아니라 첫 Tool을 경로로 기록한다.

**결과**
- 골든 status 일치 38 → 39/40, 정답 인용 21 → 22/34.
- 라우터 분류(3회 반복): 골든 40/40, 깨끗한 홀드아웃 15/16.
- 남은 문제: S-Q03은 8종 목록을 아직 못 찾아 "목록에 없음"까지는 말하지 못했다. 다음 단계(2번)의 multi-query 근거가 됐다.

## 2. 넓게 찾기 + LLM 재순위·충분성 판정 (11/07 오전)

**문제 상황**
- 11/06 화면 답변은 근거가 많은데, 질문에 꼭 필요한 근거는 아니었다.
- 출력 인용 중 골든 정답은 약 9%였고, 문항당 인용 중앙값은 9개였다.

**원인**
- 검색 후보를 수작업 점수와 문턱(4점)으로 걸렀다. 이 점수는 '필요한 근거'를 가르지 못했다.
- 원문 인용 후보를 거르는 규칙(글자쌍 2개 이상, 단계 불일치 제외)이 정답을 버렸다.
  - 예: S-Q06·S-R01은 검색 1위였지만 인용 후보에서 빠졌다.
- 병명을 넣은 질문 하나로만 검색해서 목록형 근거(8종 목록 등)를 놓쳤다.
- 찾은 근거를 거의 그대로 답변에 넘겼다. 질문에 답이 되는지는 판정하지 않았다.

**해결책** — 재현율은 '넓게 찾기'로, 정밀도는 'LLM 재순위'로 나눠 맡긴다
- 넓게 찾기(학교 행동 Tool):
  - 원 질문과 라우터가 만든 문서 용어 질문으로 각각 hybrid 검색하고 RRF로 합친다.
  - 점수 문턱과 인용 후보 규칙을 없앴다.
  - 결정적 안전장치는 유지했다: 허용 문서, 선정 쪽수, 질병·조치 불일치, DB 대조.
- 재순위(`rerank.py`, LLM 1회):
  - 모든 Tool 결과를 청크 카드로 모은다.
  - 근거마다 역할(직접 답·조건·전제 정정)과 원문 그대로의 핵심 구절을 고른다. 구절은 코드가 원문과 대조한다.
  - 하위 질문마다 답함/일부/없음과 빠진 부분을 판정한다. 하나라도 '답함'이 아니면 PARTIAL로 두고 빈 곳을 밝힌다.
- 답변 줄 단위 검사·스트리밍:
  - 걸린 줄만 빼고 통과한 줄은 바로 화면에 내보낸다.
  - 첫 줄(결론)이 걸리면 템플릿으로 바꾼다.
- 학교 행동 Tool의 두 검색을 동시에 실행했다(3.6~4.6 → 2.7~3.4초).

**결과**

| 지표 | 전 | 후 |
|---|---|---|
| 정답 1개 이상 인용(/34) | 22 | 27~29(2회) |
| 정밀도 하한 | 0.093 | 0.35 |
| 문항당 인용 | 9 | 2~3 |
| LLM 다듬은 답변 사용 | 32/34 | 35/36 |
| 응답 시간 중앙값 | 6.3초 | 10.3초 |

- 해석: '필요한 근거만'은 수치로 확인됐다.
- 대가 1: 재순위가 정답을 일부 버린다. 넓게 찾기만 했을 때는 31/34였다.
- 대가 2: 재순위 결과가 실행마다 흔들린다(27 ↔ 29).

## 3. 답변 줄 검사 오탐 제거 (11/07 오후)

**문제 상황**
- 계획은 "검사를 더 엄하게"(③)였다. 그 전에 실제 답변 128줄(34문항)을 한 줄씩 판독했다.
- 결과:

| 판정 | 줄 수 |
|---|---|
| 근거에 없는 사실 | 0 |
| 맥락 누락(조건·단계·시나리오 빠짐) | 7 |
| 검사가 막은 줄 | 6건 — **모두 정확한 줄을 잘못 막음** |

- 잘못 막은 6건 중 2건은 답변 전체가 템플릿으로 바뀌었고, 4건은 줄이 지워졌다.

**원인**
- "학교장이 신고 의무자인지는 확인되지 않았습니다" 같은 부정·미확인 문장에도 주체·강도 검사를 했다.
- 담당 동의어를 몰랐다: 행정실↔행정지원팀, 학교장↔학교의 장.
- 소제목의 담당을 줄의 주체로 상속해 검사했다.
- 모의훈련 시나리오나 다른 단계의 행동을 일반 지침처럼 써도 표시가 없었다.

**해결책** — 엄하게가 아니라 정확하게
- 미확인·안내 줄은 주체·강도 검사에서 뺐다.
- 담당 동의어를 추가했다.
- 근거에 없는 소제목 담당은 줄을 지우지 않고 중립 소제목 아래로 옮긴다.
- 시나리오·다른 단계·시간 조건('~후')이 빠진 줄에는 코드가 표시를 붙인다.
- 시나리오 근거만 인용한 첫 줄의 '네/아니요'는 지운다. 시나리오 청크는 DB 소제목으로 확인한다.

**결과**
- 템플릿 대체 2 → 0, 빠진 줄 4 → 0.
- 맥락 누락 7줄 중 5줄은 코드 표시로 해결됐다(재생 기준).
- 결론 오류였던 S-T03은 "네" → "아니요. … 보건교사는 제외"로 바뀌었다.
- 정답 인용 27~29로 변동 범위 안이었다.

## 4. 상황형 질문: 근거 나열에서 판단해 주는 답변으로 (11/07 오후)

**문제 상황**
- 승우 님이 Streamlit에 실사용 질문 2개를 넣었더니 답이 매우 나빴다(제미나이보다 못함).
  - "전교생 5명 코로나 확진, 교장이 할 일"
    - "신고가 필요한 법정감염병인 경우 신고"를 조건 판단 없이 그대로 옮겼다.
  - "담임인데 홍역이 반에 몇 명씩, 신고해야? 안 하면?"
    - 첫 줄이 주체 검사에 걸려 템플릿이 됐다.
    - 템플릿에 Tool 내부 경고문이 그대로 노출됐다.
    - 처벌은 근거 없음이었다.
- 답에 필요한 원문은 거의 다 DB에 있었다(8종 목록, 제12조, 코로나19 제4급, 유행의심 기준, 담임 3단계 역할, 벌칙 요약).

**원인** — 검색이 못 찾은 것보다, 찾을 수 있는 근거를 연결해 판단하는 단계가 없었다
- 상황 적용 단계가 없었다. 파이프라인이 "근거 찾기 → 옮기기"뿐이라 원문의 조건을 질문 사실(코로나·5명)에 대입하지 않았다.
- 답하려면 꼭 확인해야 하는 사실(질병 급수, 신고 대상 여부, 인원 → 대응 단계, 질문자 역할의 의무)을 묻지 않았다.
- 화면 기본 허용 문서가 5종이었다. 코로나19 지침, 벌칙 요약이 있는 호흡기 지침이 빠져 있었다.
- 처벌은 법령 Tool만 찾았다(Tool 칸막이).
- 답변 형식이 역할별 나열이었다.
- 실패 처리가 첫 줄 하나로 답변 전체를 템플릿으로 바꿨다.
- 골든 평가가 '정답 청크 인용'만 재서 사용자 체감을 놓쳤다.

**해결책**
- 상황 해석: 라우터가 같은 LLM 호출에서 상황과 확인 항목을 함께 낸다.
  - 상황: 질병·확진/의심·인원·범위·질문자 역할
  - 확인 항목: 신고 대상, 급수, 대응 단계, 신고 의무자, 벌칙, 역할별 할 일, 출석 인정
- 판단 기준 원문 조회(`checks.py`):
  - 확인 항목의 원문을 DB에서 직접 찾는다. Tool과 동시에 돌아 대기는 0.2~0.5초다.
  - 코드는 글자 대조만 한다(병명이 8종 목록에 있는지, '제N급' 등).
  - 찾은 원문은 선별 뒤에도 항상 남긴다.
- 판단형 답변 형식: 결론 → 상황 판단 → 지금 바로 할 일 → 이후 할 일 → 다른 담당 → 신고·법적 사항.
  - 규칙에 질문 사실을 대입한 판단은 허용한다. 단, 규칙 근거 번호를 반드시 붙인다.
- 실패 처리:
  - 첫 줄이 걸리면 이유를 알려 1회만 다시 쓴다.
  - 처벌을 물었는데 빠지면 벌칙 원문 줄을 코드가 덧붙인다.
  - 사용자 화면에는 확인하지 못한 부분만 쉬운 말로 보인다.
- 화면 기본 허용 문서를 DB 전체 10종으로 넓혔다(팀 승인). 골든 평가는 기존 5종을 유지한다.

**결과**

| 지표 | 전 | 후 |
|---|---|---|
| 상황형 15문항 루브릭(/75, Claude 1인 채점) | 52 | 73 |
| 템플릿 대체 | 2 | 0 |
| 오답 | 1 | 0 |
| 골든 정답 인용(/34) | 27 | 28 |
| 골든 기대 status 일치(/40) | 38 | 35 |
| 응답 시간 중앙값 | 12.2초 | 14.2초 |

- 오답이었던 D07 성홍열: 의료기관용 '24시간 신고'를 학교 의무처럼 썼다 → "신고 목록에 없음 + 법 근거"로 바뀌었다.
- 골든 status 하락 이유:
  - 2건은 신고 목록·제12조를 연결해 끝까지 답하게 된 것이다. 기대 status는 이전 능력 기준으로 정한 값이다.
  - 2건은 선별이 세부를 부족으로 판정한 것이다.
- 해석(가설): 개선의 핵심은 형식이 아니라 묻지 않은 판단 기준 원문을 질문마다 가져온 것이다. 형식만 바꿨을 때는 D07·D02를 고칠 수 없었다.
- 같은 날 밤 유종혁 님이 법령 벌칙 조문을 적재하고 벌칙 카드를 추가했다(a76549e, f49e07f).

## 5. Tool 호출 흐름·안전장치 점검 (11/08 오전)

**문제 상황(의문)**
- 승우 님의 의문: "주 의도 Tool 먼저 → 부족하면 추가 Tool" 구조와 Tool마다 반복하는 안전장치(허용 문서 재적용, 선정 쪽수, DB 대조)가 문제를 만들지 않는가?
  - Tool 호출을 늘린다
  - 복합 탐색을 막는다
  - 시간을 늘린다

**원인(측정으로 확인한 것)**
- 의문과 달리 호출 횟수는 많지 않았다. 51문항 중 47문항이 Tool 1회로 끝났다.
- 안전장치 비용도 거의 0이었다(쿼리 조건과 메모리 안 거르기).
- 시간의 67.5%는 LLM 세 단계(라우터·선별·작성)였다.
- 실제 비용 1: 2번째 호출 4건이 모두 헛걸음이었다. 법령 Tool은 근거 없음이었고, 그동안 2.6~4.3초가 들었다.
- 실제 비용 2: 법령 Tool이 검색 함수마다 새 DB 연결을 만들었다(호출 5회에 연결 11회, 9.9초). 법령 Tool 시간의 약 89%가 연결이었다.
- 다른 담당 골든 39문항 교차 측정에서 실제 실패 3건이 나왔다.
  - Q21 "수족구 등교중지 법적 근거": 주 의도 Tool이 근거 없음이면 다른 Tool로 넘기지 않아 막다른 길이 됐다. 학교 행동 Tool 단독은 학교보건법 제8조를 찾았다.
  - Q06: 라우팅 모호.
  - Q08: 표 행 누락.

**해결책**(승우 님 승인: 1·2번 진행, 3번 라우터 CROSSDOC 보강은 하지 않음)
1. 법령 Tool 읽기 함수 3개가 공용 드라이버를 쓴다. 연결이 끊긴 경우에만 다시 연결해 재시도한다. 유종혁 님 파일이고 팀장 승인 하에 수정했다. 적재 코드는 바꾸지 않았다.
2. 주 의도 Tool이 근거 없음이면 학교 행동 Tool로 한 번 넘긴다. 거부 카드("확정하지 않았습니다")는 넘기지 않는다. 호출 한도 3회는 그대로다.

**결과**

| 지표 | 전 | 후 |
|---|---|---|
| 법령 Tool 1회 시간 중앙값 | 2.86초 | 1.36초 |
| 새 DB 연결(55문항 전체) | 11회 | 1회 |
| 55문항 응답 시간 중앙값 | 11.64초 | 10.77초 |
| Q21 | 근거 없음 | 학교보건법 제8조·시행령 제22조로 답함 |

- Q28 거부 카드는 넘기지 않는 것을 확인했다.
- 해석: Tool 독립성 때문에 호출이 늘어난 것이 아니었다. 각 Tool의 담당 범위가 좁아서, 통합이 학교 행동 Tool과 메인 판단 기준 조회에 기대고 있었다. 이 관찰이 6번(질병 Tool이 거의 안 불림)으로 이어졌다.

## 6. 2026 질병별 지침 우선·지침 전용 질문 (11/08 오후)

**문제 상황**
1. 학교 문서(교육부 매뉴얼 2023·경기도 가이드북 2024)와 2026 질병관리청 지침이 다르게 말해도 결론이 학교 문서를 따랐다.
   - 예: 성홍열 잠복기 "1-3일"(교육부). 2026 지침은 "1~7일".
   - 예: 수족구 복귀를 학교 문서 기준으로만 답했다.
2. 11개 질병 안에서 지침에만 있는 내용을 답하지 못했다.
   - 예: "마이코플라스마 폐렴 전염기간은?" → 근거 없음. 원문은 PDF 193쪽에 있다.
- 범위: Neo4j에 적재한 질병 11개만 다룬다(승우 님 지시).

**원인** — 개별 질문이 아니라 메커니즘 문제(범위 안 16문항에서 같은 원인이 여러 질병에 반복)

| 원인 | 층 | 증거 |
|---|---|---|
| A. 질병–청크 관계(ABOUT)가 학교 문서에만 있다 | 데이터 | 경기도 133·교육부 29 vs 코로나19·홍역·수족구 지침 0. 병명 없는 지침 청크("발열이 없고, 수포가 마른 후 복귀")는 질병 근거로 인정되지 않았다 |
| B. 병명이 있어도 학교 행동 질문이면 질병 Tool을 부르지 않았다 | 메인 흐름 | 51문항 중 47문항의 첫 Tool이 학교 행동 |
| C. 선별 LLM이 Tool의 짧은 발췌만 봤다 + 별칭 버그 | 선별 | 전염기간 문장은 청크의 960번째 글자에 있었다. 별칭 설정이 '전염기간'을 '전파'로 바꿔 발췌가 '전파경로' 줄에 잡혔다 |
| D. 판본 우선 규칙이 없었다 | 선별·작성 | 지침의 '보건소·의료기관용' 표시가 등교 제한 권고까지 학교에 못 쓰게 막았다 |

- 근거 규칙: 교육부 매뉴얼 PDF 50쪽 "방역당국에서 별도의 관리지침을 제시할 경우에는 그 지침을 우선 적용함". 2026 지침 우선은 학교 문서 스스로 정한 규칙이다.

**해결책**
- A(질병 Tool, 송수림 님 파일, 팀장 승인)
  - 한 질병만 다루는 지침(수족구·홍역·인플루엔자·코로나19)의 청크를 그 질병 근거로 인정한다.
  - 소제목에 병명이 있는 청크도 인정한다.
  - 제외 문구(예: 파라인플루엔자)가 있으면 인정하지 않는다.
  - 없는 관계를 그래프 경로로 만들지 않는다.
- B(메인): 질문이 11개 질병 중 하나를 말하면 질병 Tool을 주 Tool과 **동시에** 부른다(동반 호출). 공문·절차 질문은 제외한다.
- C
  - 선별 카드에 청크 본문에서 질문 핵심어가 몰린 구간을 원문 그대로 최대 2개 붙인다.
  - 별칭 버그를 고쳤다. '전염기간'·'전염력'을 그대로 둔다.
- D
  - 근거마다 판본(2023·2024·2026)을 표시한다.
  - 다르면 결론은 2026 지침으로 쓰고, 학교 문서 기준은 아래에 함께 남긴다.

  - 판본 숫자는 줄 검사에서 제외한다.
  - 지침의 문서 성격 표시를 고쳤다: 질병 정보·등교 제한 권고는 학교에도 적용하고, 역학조사·신고는 보건소·의료기관 업무다.

## 7. 흐름으로 본 해석

- **병목이 단계마다 다음 층으로 옮겨 갔다.**
  - 1번 라우팅 → 2번 찾기·거르기 → 3번 검사 → 4번 판단 단계 → 5번 Tool 흐름 → 6번 데이터 관계와 판본
  - 한 층을 고치면 그다음 층의 문제가 드러났다.
- **"출력 형식이 아니라 내부 로직을 고친다"는 원칙이 효과의 대부분을 냈다(해석).**
  - 4번에서 형식만 바꿨을 때는 오답이 남았다. 판단 기준 원문 조회를 넣자 고쳐졌다.
  - 6번도 프롬프트 한 줄이 아니라 Tool 호출·근거 인정·선별 입력을 바꿨다.
- **결정적 안전장치는 끝까지 유지했다.** 허용 문서, 선정 쪽수, 질병 불일치, DB 대조, 원문 구절 대조, 줄 검사가 그대로다. 5번 측정에서 이 장치들의 시간 비용은 거의 0이었다.
- **LLM 호출은 질문당 3회로 고정했다.** 라우터, 재순위, 작성이고, 첫 줄 실패 시에만 1회 재작성한다. 근거마다 LLM을 부르지 않는다(합의).
- **대가는 응답 시간이다.**

| 시점 | 응답 시간 중앙값 |
|---|---|
| 11/06 | 6.3초 |
| 2번 후 | 10.3초 |
| 4번 후 | 약 11~14초 |
| 5번 후(55문항) | 10.8초 |
| 6번 후, 질병 동반 호출 질문 | 14.9초 |

  - 스트리밍(검사를 통과한 줄부터 표시)으로 체감 대기를 줄였다. 첫 줄 표시 시간은 따로 재지 않았다.

## 8. 공통 한계

- 대부분 각 1회 실행이다. 선별·충분성 LLM의 실행 간 변동(정답 인용 ±2, status ±1~2)보다 작은 차이는 개선·퇴행으로 보지 않았다.
- 상황형 15, 지침 전용 16, 교직원·홀드아웃 질문과 기대값·판정은 Claude가 만들었다. 사람 검수 전이다.
- 골든 일부(S-Q03·S-L01·S-A04)는 분석·규칙 수정에 쓰여 평가용 독립성이 약해졌다.
- 골든 정답은 학교 문서 위주라 2026 지침 근거로 맞게 답해도 정답으로 세지 않는다. 정밀도 하한도 이 때문에 낮게 나온다.
- 응답 시간은 로컬 PC에서 Aura를 대상으로 잰 값이다.
